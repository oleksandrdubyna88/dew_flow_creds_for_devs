## The problem

Two codebases that are one product lived in two unrelated folders, neither under version control:

- `D:\vscode-cred-ssh-manager` — the extension, plus **41 committed `.vsix` build artifacts** and a
  `node_modules` tree, 134 MB in total.
- `D:\cred-vault-server` — the server the extension's most-recommended feature depends on.

The extension's own README claimed the server lived "in this repository". It did not, and nothing
pointed at where it did — the only trace was a comment in an integration-test script naming a
sibling path. Neither had CI, a licence, or a deployment story; the extension's manifest was marked
`private: true` with `license: UNLICENSED`.

## What was delivered

### 1. Repository bootstrap

- `.claude/rules/shared` mounted as a submodule of `dew_flow_conventions`, per `ROLLOUT.md`.
- `.claude/settings.json` copied verbatim from the conventions reference.
- `CLAUDE.md` written to the family template, carrying only what is specific here.
- The house .NET baseline: `Directory.Build.props` (`TreatWarningsAsErrors`), central package
  management, `global.json`, `nuget.config`, and `dew_flow_creds_for_devs.slnx`.

### 2. `.gitignore`

The .NET file kept, plus a Node/TypeScript section (`node_modules/`, `out/`, `*.vsix`,
`*.tsbuildinfo`, coverage, editor noise) and a deployment-secrets section.

> **Deviation from the family convention, deliberate.** The conventions put a *nested* `.gitignore`
> in a Node subfolder rather than a section in the root file. The brief asked for a section in the
> root `.gitignore`, so that is what shipped; the two nested files that came with the projects were
> deleted so there is one source of truth.

### 3. The move

`src_vs_code/` and `src_minimalapi_server/`, excluding `node_modules`, `out`, `bin`, `obj` and all
41 `.vsix` files — 134 MB down to 614 KB. The four plan documents the extension carried were merged
into the repository-root `research/` and `todo/`, where the conventions require them.

### 4. Build and test

Both halves build and test green. The server's tests were **converted from a hand-rolled console
runner to xUnit v3 on Microsoft Testing Platform**, hosted in-process through
`WebApplicationFactory`: 30 sequential checks against a background `dotnet run` became 36 isolated
tests in 1.5 s with no port and no process management. `run-api-tests.sh` was retired.

> **Deviation:** the conventions place tests in a repository-root `tests/` mirroring `src/`. With two
> products that would be ambiguous, so tests stay inside each product's subtree.

### 5. CI

One `ci.yml`, four independent jobs — `server`, `extension`, `docker`, `plans` — so a change to one
product is never blocked by the other's toolchain. The `docker` job does not merely build the image:
it runs it, waits for the healthcheck, asserts an unauthenticated request gets 401, validates
`compose config` in all four TLS modes, and shellchecks the operator scripts.

`release.yml` keys off tag prefixes: `server-v*` pushes a multi-arch image to ghcr.io,
`extension-v*` publishes to the Marketplace — and **refuses while the publisher id is still the
placeholder**.

### 6. Marketplace preparation

MIT licence (root and mirrored into the package), `private: true` removed, `repository`/`bugs`/
`homepage`/`keywords`/`galleryBanner` added, a `CHANGELOG.md`, a trimmed `.vscodeignore`, and
`media/icon.png` at 128×128 — generated by `scripts/generate-icon.mjs`, a dependency-free rasteriser
that draws the same glyph as the SVG and encodes the PNG with `node:zlib`, because the Marketplace
rejects an SVG there and a committed binary nobody can regenerate is worse than a script.
`vsce package` succeeds with no warnings. The publisher id is a deliberate placeholder;
`docs/PUBLISHING.md` is the handover.

### 7. Deployment

`deploy/` — app + nginx + certbot, one `docker compose up -d`, four TLS modes, data in host
directories that updates never touch, and `update.sh` / `backup.sh`. Detail and the decisions behind
it: [module_deployment.md](module_deployment.md).

### 8. Review

[SECURITY_REVIEW_2026-08-23.md](SECURITY_REVIEW_2026-08-23.md). Five high-severity findings fixed
with a red-then-green test each; the remainder recorded as plans.

## Deviations from the brief, and why

| Asked | Shipped | Why |
|---|---|---|
| "certbot for HTTPS, two options: by IP and by domain" | Four modes: `domain`, `ip`, `custom`, `none` | The two asked for cannot serve a private network at all — Let's Encrypt cannot validate an internal address. `custom` is what an internal deployment actually needs |
| "maybe even automatic" updates | Manual `update.sh`, with rollback | Confirmed with the operator. Watchtower needs the Docker socket, which is root on the host; for a credential server that converts a registry compromise into a full one |
| — | The extension **rejects self-signed certificates** | Not in the brief, and it invalidates the obvious internal-network plan. It uses `fetch()` with no certificate override. Documented prominently rather than discovered in production |

## What this changed that was not planned

Three defects surfaced only because the work was verified rather than reasoned about, and each would
have shipped:

1. **`docker compose up -d` crashed on first boot on Linux** — a root-owned bind mount against an
   unprivileged container. Invisible on Docker Desktop, whose bind mounts are permissive. Fixed with
   the one-shot `init` service.
2. **`nginx:alpine` has no `openssl`**, so the original self-signed-placeholder scheme exited 127.
   That prompted a better design: no placeholder at all, and an honest 503 until a certificate
   exists.
3. **nginx's stock `default.conf` shadowed the API**, because `conf.d` loads alphabetically.
