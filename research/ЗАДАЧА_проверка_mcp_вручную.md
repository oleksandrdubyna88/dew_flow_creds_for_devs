# ЗАДАЧА — проверить MCP руками, за один заход

> Status: **ПРОЙДЕНО ВРУЧНУЮ, 2026-08-29.** Владелец подтвердил прохождение на настоящем Claude
> Code с настоящим окном согласия. Проход покрывал поверхность **0.65.0–0.78.1**
> ([PLAN_mcp_server.md](PLAN_mcp_server.md)); всё, что вышло после — папки (0.85.0) и настройки
> генерации (0.86.0) — этим проходом **не покрыто** и вынесено в
> [ЗАДАЧА_проверка_mcp_папки_и_генерация.md](ЗАДАЧА_проверка_mcp_папки_и_генерация.md).
>
> Автотесты проверяют половины; здесь проверялось то, что может проверить только человек:
> настоящий MCP-клиент, настоящее окно согласия и то, как это читается глазами.
>
> Порядок неслучаен: каждый пункт опирается на предыдущий. Пройти сверху вниз ≈ 30 минут.

## Подготовка (5 минут)

**1. Расширение.** Установлено 0.78.1 — проверить: `Ctrl+Shift+P` → *Extensions: Show Installed*,
CredsForDevs, версия 0.78.1. Окно перезагрузить (`Developer: Reload Window`).

**2. Бинарь.** Уже собран:

```
D:\rsd\dew_flow_creds_for_devs\src_mcp\src\bin\Debug\net10.0\creds-mcp.exe
```

Если нет — `dotnet build src_mcp/src/CredsMcp.csproj`.

**3. Подключить его к Claude Code.** В `~/.claude.json` (или `.mcp.json` в проекте):

```json
{ "mcpServers": { "creds": { "command": "D:\\rsd\\dew_flow_creds_for_devs\\src_mcp\\src\\bin\\Debug\\net10.0\\creds-mcp.exe" } } }
```

Перезапустить Claude Code. `/mcp` должен показать `creds` и восемь инструментов.

> **Кнопку «Install the MCP Server…» пока проверить нельзя** — тега `mcp-v*` ещё нет, релиза не
> существует. Это последний пункт списка, и он ждёт тега.

**4. Подопытная запись.** Завести SSH-запись на хост, куда вы ходите **по ключу** — папка
«Servers», имя `mcp-test`. Поле пароля не заполнять или заполнить мусором: его будет ротировать
пункт 4, и на вход по ключу это не влияет. **Не берите продовую запись.**

## 1. Пока не включено — не видно ничего

| Делаем | Должно быть |
|---|---|
| Спросить агента: «какие у меня есть доступы?» | `creds_list` вернул **пустой список** и агент говорит, что ничего не открыто |

**Баг, если**: вернулась хоть одна запись. Хранилище невидимо агенту по умолчанию — это главное
обещание всей конструкции.

## 2. Лестница и наследование

1. Правый клик по `mcp-test` → **Edit** → секция **Agent access**. Все шесть выключены.
2. Включить **Usable by agents**. Смотреть: *Visible to agents* включился **сам** и заблокировался.
3. Save. Спросить агента снова.

| Должно быть |
|---|
| Запись видна. В ответе есть `host`, `user`, `port`, **нет** пароля. `can.use = true`, `can.edit = false` |

4. Правый клик по папке **Servers** → **Edit** → включить **Visible to agents** → Save.
5. Завести в ней вторую запись, ничего ей не включая. Спросить агента.

| Должно быть |
|---|
| Вторая запись тоже видна — она унаследовала настройку папки |

**Баг, если**: удалось выключить *Visible* при включённом *Usable*; или наследование не сработало;
или в ответе оказался пароль.

## 3. Использование — и то, что спрашивают каждый раз

Попросить: «выполни `uname -a` на mcp-test».

| Должно быть |
|---|
| В VS Code всплыло окно: **Claude Code хочет run a command on «mcp-test»** и **сама команда** |
| Нажать **Allow** → агент получил вывод |
| Повторить ту же просьбу → окно всплыло **снова** |

**Баг, если**: второй раз не спросили. Переключатель говорит «спрашивать можно», окно — «этот вызов
происходит», каждый раз.

Теперь **Deny** на третьей попытке → агент получает отказ, команда не выполняется.

## 4. Ротация — и главная проверка этого релиза

Попросить дословно:

> выполни creds_rotate для mcp-test со statement: `echo '{{creds:new}}'`

| Должно быть |
|---|
| Окно согласия показывает статью **с `{{creds:new}}` внутри**, а не со значением |
| После Allow агент отвечает `"rotated": true` |
| **В выводе на месте секрета — `<CREDS_MASKED:PASSWORD>`**, а не сам пароль |
| Правый клик по записи → в дереве появилась/выросла история версий |

**Это главная проверка.** `echo` печатает то, что ему дали, — то есть только что сгенерированный
пароль. Если агент увидел его открытым текстом, значит маскировщик не сработал: это ровно тот
дефект, который нашли и починили в 0.76.0.

**Баг, если**: в окне согласия виден настоящий пароль; или в ответе агента виден настоящий пароль;
или история версий не выросла.

Попробовать ещё: `creds_rotate` со `statement: "true"` (без плейсхолдера) → **отказ** с объяснением,
что нужен `{{creds:new}}`. Ничего не выполнилось, ничего не записалось.

## 5. Создание

1. Папка **Servers** → **Edit** → включить **Agents may create entries** → Save.
2. Попросить: «создай запись `app-03`, kind ssh, host `app-03.example.internal`, и **сгенерируй
   секрет сам** (secretKind password)».

| Должно быть |
|---|
| Окно: **create an entry in** … `app-03 (ssh) в "Servers"` |
| После Allow запись появилась в дереве, у неё есть пароль |
| **Агент не назвал пароль** — он его не видел |

3. Теперь попросить создать `app-04`, **передав секрет самому** (`secret: "supplied-by-agent"`).
   Запись появилась. Этот случай попадёт в журнал отдельной строкой — проверим в пункте 8.

**Баг, если**: агент выбрал папку сам при двух открытых; или создал при выключенном переключателе;
или сгенерированный пароль оказался в ответе.

## 6. Удаление — только в корзину

1. У `app-03` → **Edit** → включить **Agents may delete what they created** → Save.
2. Попросить удалить `app-03`.

| Должно быть |
|---|
| Окно говорит **move to the Trash**, а не «delete» |
| После Allow запись в папке **Trash**, а не исчезла |
| Ответ агенту содержит `"restorable": true` |

3. Попросить удалить `mcp-test` (её агент **не** создавал).

| Должно быть |
|---|
| **Отказ**, и в тексте названо, какой переключатель нужен. Никого не спросили |

**Баг, если**: удалилось навсегда; или удалилась запись, созданная человеком, при узком объёме.

## 7. Чего мы не умеем генерировать

Попросить: «создай запись `gateway-cert` и сгенерируй секрет `secretKind: x509`».

| Должно быть |
|---|
| **Отказ**, и в нём написано, что сертификаты выдаёт удостоверяющий центр |
| Ничего не создалось, никого не спросили |

Ещё: `secretKind: "supersecret"` → другой отказ, со списком допустимых слов.

## 8. Журнал: ⋯ → MCP logs

| Фильтр | Что должно быть после пунктов 1–7 |
|---|---|
| **Everything** | все вызовы: query, rotate, create, delete |
| **Refused** | Deny из пункта 3, отказ удаления из 6 |
| **Secrets replaced** | одна строка — ротация из пункта 4 |
| **Secrets from the agent** | одна строка — `app-04` из пункта 5 |
| **Could not generate** | одна строка — `gateway-cert` из пункта 7 |

**Баг, если**: отклонённая ротация посчиталась как «заменённый секрет»; или отказ из пункта 7 попал
в «Refused» вместо своего фильтра; или в детали строки виден настоящий секрет.

Проверить ещё: перезагрузить окно (`Developer: Reload Window`) → журнал **сохранился**. Он читает
файлы аудита, а не память окна.

## 9. Показать запись по id

Взять `id` любой записи из ответа `creds_list`. ⋯ → **Show Entry by id…** → вставить.

| Должно быть |
|---|
| Дерево раскрылось до записи и подсветило её |
| Если в фильтре дерева что-то набрано — фильтр **сбросился** |
| Несуществующий id → понятное сообщение, что такого нет ни в одном разблокированном аккаунте |

## 10. Значки в дереве — посмотреть глазами

Глядя на дерево после пунктов 2–6:

- У записей с включённым доступом под значком **пять полосок**; горят столько, сколько ступеней
  включено, слева направо: зелёная → голубая → янтарная → фиолетовая → красная.
- У записей **без** доступа значок обычный, как у VS Code, — полосок нет вовсе.
- Переключить тему (светлая ↔ тёмная) — полоски читаются в обеих.

**Смотреть придирчиво**: глифы для записей с доступом рисуем мы, а не редактор. Если они выбиваются
из набора VS Code сильнее, чем терпимо, — это стоит сказать.

## 11. Ждёт релиза: кнопки установки

Проверять **после** того, как будет выпущен тег `mcp-v0.1.0`:

1. ⋯ → **Install the MCP Server…** → скачивает, кладёт в хранилище расширения, **кладёт в буфер
   конфиг** и говорит, куда его вставить.
2. Проверить, что путь в конфиге — полный (бинарь намеренно **не** кладётся в PATH).
3. Испортить `.sha256` в релизе (или подменить файл) → установка должна **отказаться**, а не
   поставить.
4. То же для **Install `creds`**.

## 12. Из WSL — пройдено 2026-08-28

Мост реализован ([../research/PLAN_mcp_wsl_bridge.md](../research/PLAN_mcp_wsl_bridge.md)), и этот
проход сделан на настоящем Claude Code внутри дистрибутива Ubuntu против окна VS Code 0.80.7 на
Windows. Как подключено:

```bash
# Linux-бинарь (framework-dependent, dotnet 10 в дистрибутиве уже есть)
dotnet publish -c Release -r linux-x64 --self-contained false -p:PublishAot=false   -o ~/.local/share/creds-mcp                      # из чистой копии исходников в /tmp

claude mcp add -s user creds   -e CREDS_MCP_WINDOWS_BINARY=/mnt/d/rsd/dew_flow_creds_for_devs/src_mcp/src/bin/Debug/net10.0/creds-mcp.exe   -- ~/.local/share/creds-mcp/creds-mcp
```

| Проверено | Результат |
|---|---|
| `claude mcp list` | `creds ✔ Connected` |
| `creds_list` через настоящего агента | вернул запись из хранилища на Windows, с `can`, без секрета |
| `creds_create` (оба пути: `secretKind` и свой `secret`) | **отказ до всякого окна согласия** — см. находку ниже |

**Находка, требующая решения владельца.** `creds_list` отдаёт записи `can.create: true`, а
`creds_create` отвечает *«No folder is open to agents for creating entries»* и никого не спрашивает.
Противоречия в коде нет: `capabilitiesOf` строит `can.create` из переключателя **записи** (своего или
унаследованного от папки), а `creatableFolders` требует переключатель **самой папки**
(`opensToCreation`, папки создание не наследуют — это записано намеренно). Но агенту это читается как
разрешение, которого нет: он планирует создание, тратит вызов и получает отказ. Отказ хороший и
называет переключатель. Варианты: считать `can.create` от папки, а не от записи; или убрать поле из
листинга записей, раз оно про папку. Не трогал — это изменение видимого агентам контракта.

**Чтобы пройти пункт 5 из WSL**, нужно включить *Agents may create entries* на самой папке
(правый клик по папке → Edit → Agent access), а не только на записи.

## Что записать по итогам

Для каждого пункта — «ок» или что именно разошлось с ожиданием. Особо:

- **любой случай, где секрет виден** — это стоп-находка, всё остальное подождёт;
- любое окно согласия, которое не всплыло;
- любой отказ, из текста которого непонятно, что включить.

## Что этот проход дал

Ценность ручного прохода не в галочках, а в том, что он нашёл. Три вещи, каждая из которых
пережила бы любой автотест, потому что все они про стык между половинами:

**1. `can.create` у записи и «папка открыта для создания» — не одно и то же.** `creds_list` отдавал
запись с `can.create: true` (её собственный или унаследованный переключатель), а `creatableFolders`
требовал переключатель на **самой папке** и наследование делать отказывался. Агент видел «можно»,
звал `creds_create` и получал отказ. Отказ был хороший и называл переключатель — цена в один
потраченный вызов и вводящее в заблуждение поле. **Починено 2026-08-28**: наследование сведено к
одному правилу, оба конца теперь поднимаются по цепочке
([PLAN_agent_folder_ops.md](PLAN_agent_folder_ops.md)).

**2. Дверь брокера не открывалась после перезагрузки окна.** Слушатель поднимался только на первый
*Share with Claude Code* — дверь, которой MCP не пользуется: агент сам запускает `creds-mcp` и ищет
окно по объявлению, которое пишет этот слушатель. Симптом — «No CredsForDevs window answered» при
открытом окне и включённых переключателях, дословно то же, что говорит закрытое окно. **Починено в
0.84.0**: окно, в котором что-то открыто агентам, поднимает слушателя на активации.

**3. Из WSL агент до окна не дотягивался вовсе.** `127.0.0.1` внутри дистрибутива — loopback
виртуальной машины. **Починено**: `creds-mcp` перезапускает себя на Windows через interop
([PLAN_mcp_wsl_bridge.md](PLAN_mcp_wsl_bridge.md)), выпущено как `mcp-v0.2.0`.

## Что этим проходом НЕ покрыто

Документ описывает поверхность до 0.78.1. После него вышли два релиза, добавивших к агентской
поверхности целый объект и целую группу параметров:

- **Папки (0.85.0)** — `creds_folders`, `creds_create_folder`, `creds_edit_folder`,
  `creds_delete_folder`, четыре новых переключателя, правило «перемещение требует права с обеих
  сторон» и запрет на изменение самих переключателей.
- **Настройки генерации (0.86.0)** — длина, наборы символов, число слов и разделитель у
  `creds_create` и `creds_rotate`, плюс отказ при пустом наборе символов.

Из этого руками подтверждено ровно одно: агент **создал** папку. Остальное — новый проход:
[ЗАДАЧА_проверка_mcp_папки_и_генерация.md](ЗАДАЧА_проверка_mcp_папки_и_генерация.md).
