> писался как «сознательно не сделан»: маршрут перечисления позволяет вычислять, какие имена
> включены, тогда как 404 одинаков для «нет такого имени» и «имя есть, но не включено», и это
> ровно то, что не даёт их перебирать. Затем условие изменилось: CLI, которому `ls` нужнее всего,
> работает на Remote-SSH хосте, где реестр лежит на машине по ту сторону моста и с диска не
> читается. Владелец принял решение явно, и оно записано в `Program.cs:ListAsync` — маршрут
> раскрывает имена и виды, никогда адрес и ничего хранимого. Проверено вживую 2026-08-26: справка
> установленного бинарника печатает `creds ls`.

> **Два дефекта, найденных уже после «готово», и оба — интеграционным тестом, которого не было:**
> Б-1 (успешный `env`/`vpn-*` отчитывался кодом 95) и — серьёзнее — `/v1/use/exportEnv` был

> таблицы совпадают, и ни один не проверял, что бинарь вообще может поговорить с брокером.

> **Отклонение от §4:** контракт встраивается как EmbeddedResource, а не генерируется в

## 1. Симптом

Разработчик живёт в терминале — iTerm, Alacritty, Ghostty, tmux — и часто при закрытом редакторе.
Сейчас единственный способ дать чему-то снаружи воспользоваться секретом: открыть VS Code, найти
запись, нажать *Share with Claude Code…*, вставить из буфера сниппет вида
`node …/agentCli.js ssh <port>.<secret> -- <команда>`. Путь к `agentCli.js` вычисляется рядом с
работающей сборкой расширения (`extension.ts:1187`) — то есть привязан к конкретной установке
конкретного расширения. Инструмент остаётся «привязанным к окну редактора».

**Цель:** `creds ssh prod-db`, `creds run -- aws s3 ls`, `creds db staging -- 'select 1'` из любого
терминала; секрет не попадает в терминал, подтверждение — в UI VS Code.

## 2. Что уже есть — примерно три четверти механизма

**`agentCli.ts` + `agentCliArgs.ts` — это уже работающий headless-клиент**, без `vscode`:

- Транспорт: `fetch` на `http://127.0.0.1:<port>` с `AbortSignal.timeout` (`agentCli.ts:54-79`).
- **Обнаружение брокера — только из токена**: порт и секрет оба в строке `<port>.<secret>`
  (`grantToken.ts:29-53`). Файла сервисов нет, и по документации это сознательно.
- `isOurBroker()` (`agentCli.ts:87-98`) дёргает неаутентифицированный `/v1/health` и проверяет
  `service === 'creds-for-devs-agent'` **до** отправки токена — защита от того, что порт закрытого
  окна переиспользован чужим процессом.
- Все глаголы разведены (`ROUTES`, `agentCli.ts:150-159`): `ssh`, `terminal`, `db`, `run`, `script`,
  `env`, `vpn-up`, `vpn-down`.
- Коды выхода: полоса 90–99 под отказы механизма (`agentCli.ts:27-38`); **код выхода удалённой
  команды проходит наружу без изменений** (`:209`).
- `scripts/agent-broker-itest.cjs` поднимает настоящий сервер и запускает настоящий CLI подпроцессом
  (`:125-131`) — headless-путь доказан.

Значит **протокол проектировать не нужно**. Новый бинарь — второй клиент того же контракта.

## 3. Что мешает прямо сейчас

**Б-1. Живой баг в продакшене.** `agentCli.main` после `status === 200` особо обрабатывает только
`terminal` (`agentCli.ts:188-191`), остальное считает `Partial<ExecResponseBody>` (`:195-209`). Но
`credential:exportEnv` возвращает `{written: string[]}`, а `vpn:up`/`down` — `{opened: boolean}`: ни
у того, ни у другого нет `exitCode`. Поэтому **успешный** `env`/`vpn-up`/`vpn-down` ничего не печатает
и выходит с кодом **95 (`brokerFailure`)**. Чинится первым, отдельно от всего плана.

**Б-2. Нет имён.** `creds ssh prod-db` подразумевает справочник «имя → грант». Сейчас грант —
одноразовая вставка из буфера, живёт в памяти окна.

**Б-3. Нет места установки.** Путь к CLI всегда внутри каталога расширения.

## 4. .NET Native AOT — почему это правильный выбор и что он влечёт

Владелец выбрал ту же технологию, что у сервера, и это снимает целый класс вопросов:

- **Один тулчейн на репозиторий.** Уже есть `global.json`, `dotnet` в CI, `actions/setup-dotnet@v4`,
  опыт с `PublishAot` и с его анализаторами (`CredVaultServer.csproj`: `PublishAot=true`,
  `StripSymbols=true`, точечный `NoWarn` с объяснением). Rust добавил бы второй язык и второй CI-путь
  ради одного бинаря.
- **Ровно те же четыре RID'а уже собираются** для сервера (`release.yml:98-150`), включая нетривиальные
  `linux-arm64` (`ubuntu-24.04-arm`) и `win-arm64` (`windows-11-arm`), и с уже решённой мелочью —
  на Linux ставится `clang` + `zlib1g-dev`, потому что AOT линкуется хостовым тулчейном.
- **AOT-анализаторы работают на обычной сборке**, а не только на релизном раннере — несовместимый
  паттерн падает на компиляции. Это ровно то свойство, ради которого сервер написан так, как написан.

**Следствие, которое надо принять сознательно:** появляется второй клиент одного протокола на другом
языке. Контракт (`brokerProtocol.ts`) перестаёт быть «общим модулем» и становится **спецификацией с
двумя реализациями**. Как не дать им разойтись:

1. Маленький скрипт выгружает из `brokerProtocol.ts` коды ошибок, коды выхода, имена маршрутов и
   `SERVICE_NAME` в **`contract/broker-v1.json`**.
2. C#-проект читает этот JSON **на сборке** (MSBuild-таргет + генератор в `obj/`), а не в рантайме —
   константы попадают в бинарь, JSON с собой не едет.
3. Два теста: TS-таблица == JSON, C#-таблица == JSON. Расхождение — красный тест, а не загадка в
   чужом терминале.

**JSON без рефлексии.** У AOT нет `JsonSerializer` по рефлексии — нужен
`JsonSerializerContext` с `[JsonSerializable]`, ровно как в `AppJsonContext.cs` сервера. Тела запросов
и ответов брокера маленькие и известны; это не проблема, а требование, которое надо помнить с первой
строки.

**Размер и старт.** Сервер уже показывает, что AOT-бинарь приемлем; для CLI важнее старт — он
запускается на каждую команду в терминале, и здесь AOT выигрывает у node особенно заметно
(нет прогрева рантайма). Замер холодного старта — в DoD.

## 5. Именованные гранты (Б-2)

Гранты умирают с окном — это и есть вся история отзыва (`grantRegistry.ts` — карта в памяти). Имя
должно жить дольше, но **секрет — нет**.

- В расширении — команда **`Enable CLI Access…`** на записи: даёт **имя-псевдоним** и сохраняет
  **только** `имя → (accountId, entityId, kind)` в `globalState` (пломбированном с 0.57.0).
  **Ни токена, ни секрета там нет.**
- `creds ssh prod-db` идёт **с именем**, не с токеном. Новый маршрут `POST /v1/grant` с телом
  `{alias}`: сервер находит псевдоним, минтит свежий грант и выполняет действие в том же вызове.
  Согласие — как обычно, модалом.
- Токен перестаёт путешествовать через буфер обмена для CLI-пути. Псевдоним — не секрет; возможность
  им воспользоваться даёт только живое окно плюс согласие человека.
- **Порт всё ещё надо найти.** Единственный новый файл: `<globalStorage>/cli-endpoint.json` c
  `{port, pipe, pid, startedAt}`, права 0600 через существующий `lockToOwner`
  (`materializedKeys.ts`). Пишется при старте брокера, удаляется в `dispose`. **Секрета не содержит.**
  Несколько окон — CLI показывает выбор или берёт по `--window`.

## 6. Форма команд

```
creds ls                          # псевдонимы, включённые для CLI
creds ssh <alias> [-- cmd…]       # exec; без -- открывает интерактивный терминал в VS Code
creds run <alias>                 # сохранённая команда
creds script <alias>
creds db <alias> -- "select 1"
creds env <alias>                 # печатает ИМЕНА переменных, не значения
creds vpn up|down <alias>
creds doctor                      # какие окна найдены, отвечает ли health, версия контракта
```

`creds doctor` существует потому, что «не работает» имеет пять разных причин (окно закрыто, порт
занят чужим, контракт разошёлся, псевдоним не включён, согласия нет), и человек должен их различать.

## 7. Сборка и поставка

**Проект:** `src_cli/src/CredsCli.csproj` + `src_cli/tests/CredsCli.Tests.csproj` — та же раскладка,
что у сервера (`src/` + `tests/`). `PublishAot=true`, `StripSymbols=true`, `InvariantGlobalization`

**CI:** новый `.github/workflows/ci-cli.yml` — path-filtered на `src_cli/**`, шаги
`dotnet build` → `dotnet test`. По образцу `ci-server.yml`.

**Релиз:** новый job `cli-binaries` в `release.yml`, срабатывающий на тег **`cli-v*`** (у расширения
`extension-v*`, у сервера `server-v*` — третий префикс, чтобы CLI релизился независимо). Матрица —
**копия серверной**, включая раннеры и установку тулчейна:

| rid | runner |
|---|---|
| `linux-x64` | `ubuntu-latest` |
| `linux-arm64` | `ubuntu-24.04-arm` |
| `win-x64` | `windows-latest` |
| `win-arm64` | `windows-11-arm` |

Упаковка — как у сервера: `creds-<version>-<rid>.tar.gz` / `.zip`, приложенные к GitHub release.
Плюс `checksums.txt` (у сервера его нет; для инструмента, который люди будут скачивать и класть в
PATH, контрольные суммы — минимальная приличность).

## 9. План тестирования

- Б-1: красный тест на каждый из трёх глаголов (`env`, `vpn-up`, `vpn-down`).
- Контракт: TS == JSON == C# (два теста, по одному в каждом языке).
- Псевдонимы: включение/выключение; **в `globalState` нет ни токена, ни секрета** (тест по
  сериализованному состоянию); неизвестный псевдоним → 404 без намёка на существование.
- Endpoint-файл: создаётся/удаляется, права 0600, два окна → выбор, мёртвый pid → не пытаемся
  отправить.
- Health-проба обязательна: подложить чужой сервер на порт — CLI отказывается, ничего не отправив.
- Согласие: первый вызов открывает модал; отказ → 92; таймаут → 97.
- E2E: `creds ssh <alias> -- echo hi` через настоящий бинарь и настоящий брокер, **на win-x64 и
  linux-x64 как минимум**.
- **Замер холодного старта** бинаря против `node agentCli.js` — в CHANGELOG.
