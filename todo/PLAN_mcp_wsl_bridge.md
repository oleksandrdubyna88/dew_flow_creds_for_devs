# PLAN — `creds-mcp` из WSL: агент внутри дистрибутива и окно на Windows

> Status: **plan only, ничего не реализовано.** Хвост
> [../research/PLAN_mcp_server.md](../research/PLAN_mcp_server.md) — единственный невыполненный
> пункт его Definition of Done. Написан по-русски, как и родительский план.
>
> Опора: `src_broker_client/src/WslInterop.cs` (`WindowsBridge`), `src_cli/src/AgentRelay.cs` и
> `src_cli/src/RelayPipe.cs` — там этот мост уже работает для `creds`.

## Симптом

Claude Code часто запускается **внутри WSL**. Он стартует `creds-mcp` как свой дочерний процесс —
и этот процесс оказывается в дистрибутиве, а окно VS Code с брокером на Windows.

`127.0.0.1` внутри WSL2 — это loopback виртуальной машины, где ничего нашего не слушает. Значит:

- `Endpoints.DirectoryHere()` смотрит в `~/.config/Code/User/globalStorage/...`, которого в
  дистрибутиве нет (папка расширения — на Windows);
- даже найдя порт, `BrokerClient` до него не дотянется.

Итог, который увидит человек: агент говорит «нет открытого окна CredsForDevs», хотя окно открыто
на том же компьютере. Сообщение верное и бесполезное.

## Что уже готово

**Мост есть, его просто никто не зовёт.** `WindowsBridge` в `src_broker_client` стал инстансом на
бинарь именно ради этого случая:

```csharp
public static WindowsBridge Creds { get; } = new("creds.exe", BinaryOverrideVariable);
```

`creds` пользуется им двумя способами, и оба нужны здесь:

| способ | где | что делает |
|---|---|---|
| `Relay(args)` | `Program.Main` | перезапускает вызов на Windows, унаследовав потоки |
| `StartPiped(args)` | `AgentRelay` | запускает Windows-процесс с pipe'ами, которыми владеет вызывающий |

Целостность двоичных данных через этот мост измерена (2026-08-26): 64 КБ случайных байт вернулись с
тем же SHA-256.

## Решение

**`creds-mcp` внутри WSL перезапускает себя на Windows и качает stdio через interop.**

Это `StartPiped`, а не `Relay`: MCP — это долгоживущий JSON-RPC поток в обе стороны, а не вызов с
кодом возврата. Linux-процесс становится насосом:

```
MCP-клиент ──stdin──► creds-mcp (Linux) ──pipe──► creds-mcp.exe (Windows) ──loopback──► окно
           ◄─stdout──                   ◄─pipe──
```

### Что нужно сделать

1. **Свой `WindowsBridge` для этого бинаря.** `new("creds-mcp.exe", "CREDS_MCP_WINDOWS_BINARY")` —
   отдельная переменная окружения по причине, уже записанной в `WslInterop.cs`: указание одного
   бинаря на нестандартный путь не должно перенаправлять другой.
2. **Решение о перезапуске — до всего остального.** `WslInterop.ShouldRelayHere()` уже отвечает на
   этот вопрос двумя независимыми признаками (`WSL_DISTRO_NAME` и `/proc/version`) и содержит
   защиту от бесконечной рекурсии (`CREDS_RELAYED_FROM_WSL`). Проверять до `--help`? Нет: `--help`
   отвечает одинаково с обеих сторон и лишний процесс ради него не нужен.
3. **Насос на два направления, без переупаковки.** Байты идут как есть: JSON-RPC — это строки, но
   насос, который их разбирает, — это ещё одно место, где протокол можно сломать. `stderr`
   наследуется, чтобы диагностика с Windows-стороны доходила до клиента.
4. **Закрытие с обеих сторон.** Клиент закрывает stdin — насос закрывает stdin дочернего; дочерний
   умирает — насос выходит с его кодом. Ни один из двух процессов не должен пережить другой: MCP-
   клиент считает сервер живым, пока жив процесс, который он запустил.

### Чего делать НЕ надо

**Не пытаться найти папку endpoints из Linux.** Она есть на Windows, путь к ней зависит от версии
и издания VS Code, а `/mnt/c/Users/...` — догадка, которая сломается на первой машине с диском не
`C:`. Windows-половина уже умеет её находить; пусть она этим и занимается.

**Не заводить сетевой мост.** Ровно та причина, что записана в `WslInterop.cs`: ничего не должно
начать слушать в новом месте. Брокер остаётся loopback-only.

  `CREDS_RELAYED_FROM_WSL=1` (то есть заведомо БЕЗ перезапуска) и с фальшивым `WSL_DISTRO_NAME`
  и `CREDS_MCP_WINDOWS_BINARY`, указывающим на скрипт-эхо, — и проверяет, что через насос проходит
  полный handshake. Настоящий WSL в CI недоступен, но насос проверяем без него.
- Ручной, один раз: Claude Code внутри Ubuntu-24.04, `creds_list` возвращает записи из окна на
  Windows.

## Definition of Done

- [ ] `creds-mcp` в дистрибутиве WSL отвечает на `initialize`, `tools/list` и `tools/call`, беря
      ответы у окна на Windows.
- [ ] Ничего не начинает слушать в новом месте.
- [ ] Закрытие клиента убивает обе половины; смерть Windows-половины завершает Linux-половину.
- [ ] `--help` работает с обеих сторон без запуска второго процесса.
- [ ] Второй бинарь имеет свою переменную override, и это тест.
- [ ] Интеграционный тест гоняет насос без настоящего WSL.
- [ ] Пункт DoD родительского плана отмечен, план промотирован.
