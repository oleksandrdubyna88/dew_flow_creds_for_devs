# PLAN — `creds`: системный CLI вне VS Code

> Status: **plan only, nothing implemented yet.** Scope: новый самостоятельный бинарь (Rust или
> .NET Native AOT — **решение владельца 2026-08-25: отдельный бинарь, не обёртка над node**), плюс
> небольшие правки в расширении: реестр именованных грантов и один баг в существующем CLI.
>
> Related docs: [module_extension.md](../research/module_extension.md#the-agent-broker--using-a-credential-without-handing-it-over),
> [architecture.md](../research/architecture.md), [PLAN_audit_roadmap_2026_08_25.md](PLAN_audit_roadmap_2026_08_25.md).
> Это **не** пункт D8 дорожной карты (MCP-сервер) — D8 отложен владельцем; здесь речь о системной
> команде `creds`.

---

## 1. Симптом

Разработчик живёт в терминале — iTerm, Alacritty, Ghostty, tmux — и часто при закрытом редакторе.
Сейчас единственный способ дать чему-то снаружи воспользоваться секретом: открыть VS Code, найти
запись, нажать *Share with Claude Code…*, вставить из буфера сниппет вида
`node …/agentCli.js ssh <port>.<secret> -- <команда>`. Путь к `agentCli.js` вычисляется рядом с
работающей сборкой расширения (`extension.ts:1187`), то есть привязан к конкретной установке
конкретного расширения. Инструмент остаётся «привязанным к окну редактора».

**Цель:** `creds ssh prod-db`, `creds run -- aws s3 ls`, `creds db staging -- 'select 1'` из любого
терминала; секрет не попадает в терминал, подтверждение — в UI VS Code.

## 2. Что уже есть — примерно три четверти

**`agentCli.ts` + `agentCliArgs.ts` — это уже работающий CLI**, без `vscode`, под обычным node:

- Транспорт: `fetch` на `http://127.0.0.1:<port>` с `AbortSignal.timeout` (`agentCli.ts:54-79`).
- **Обнаружение брокера — только из токена**: порт и секрет оба лежат в строке `<port>.<secret>`
  (`grantToken.ts:29-53`). Никакого файла сервисов нет и, по документации, сознательно.
- `isOurBroker()` (`agentCli.ts:87-98`) сначала дёргает неаутентифицированный `/v1/health` и
  проверяет `service === 'creds-for-devs-agent'` — **до** отправки токена. Защита от того, что порт
  закрытого окна переиспользован чужим процессом.
- Все возможности брокера уже разведены по глаголам (`ROUTES`, `agentCli.ts:150-159`):
  `ssh` → `ssh:exec`, `terminal` → `ssh:terminal`, `db` → `db:query`, `run` → `terminal:run`,
  `script` → `script:run`, `env` → `credential:exportEnv`, `vpn-up`/`vpn-down` → `vpn:up`/`down`.
- Коды выхода: зарезервированная полоса 90–99 под отказы механизма (`agentCli.ts:27-38`), а **код
  выхода удалённой команды проходит наружу без изменений** (`:209`) — `&&` и `$?` вокруг вызова
  ведут себя нормально.
- `scripts/agent-broker-itest.cjs` уже поднимает настоящий сервер, гоняет настоящий HTTP и
  запускает настоящий CLI как подпроцесс (`:125-131`) — headless-путь доказан.

Значит **протокол проектировать не нужно**: `brokerProtocol.ts` — общий чистый контракт, а новый
бинарь становится вторым его клиентом.

## 3. Что мешает прямо сейчас

**Б-1. Реальный баг, уже в продакшене.** `agentCli.main` после `status === 200` особым образом
обрабатывает только `terminal` (`agentCli.ts:188-191`), а всё остальное считает
`Partial<ExecResponseBody>` (`:195-209`). Но `credential:exportEnv` возвращает `{written: string[]}`,
а `vpn:up`/`down` — `{opened: boolean}`: ни у того, ни у другого нет `exitCode`. Поэтому **успешный**
`env`/`vpn-up`/`vpn-down` ничего не печатает и выходит с кодом **95 (`brokerFailure`)`**. Это чинится
отдельно и раньше всего остального (см. §7 шаг 0) — баг живой независимо от этого плана.

**Б-2. Нет имён.** `creds ssh prod-db` подразумевает локальный справочник «имя → грант». Сейчас
грант — одноразовая вставка из буфера, живёт в памяти окна и умирает с ним.

**Б-3. Нет места установки.** Путь к CLI сегодня всегда внутри каталога расширения. Системная
команда должна ставиться независимо и обновляться независимо.

## 4. Решение владельца и его следствия

Выбран **отдельный лёгкий бинарь**, а не обёртка над `node agentCli.js`. Следствия, которые надо
принять сознательно:

- **Плюс:** нет зависимости от node на машине; один файл; быстрый старт; настоящий системный хелпер.
- **Минус:** появляется второй клиент того же протокола на другом языке — а значит **контракт надо
  зафиксировать так, чтобы он не разошёлся**. `brokerProtocol.ts` перестаёт быть «общим модулем» и
  становится спецификацией, у которой две реализации.
- Язык: **Rust**. В монорепозитории уже есть Rust-практика (`dew_flow_sidecar_rust` в семействе), а
  для .NET Native AOT сюда пришлось бы тащить SDK в репозиторий, где сейчас только TypeScript.
  Итог: `src_cli_rust/` рядом с `src_vs_code/` и `src_minimalapi_server/`.

**Как не дать контракту разойтись** (это главное архитектурное решение плана):
`brokerProtocol.ts` получает генератор — маленький скрипт, который выгружает коды ошибок, коды
выхода, имена маршрутов и `SERVICE_NAME` в JSON (`contract/broker-v1.json`), а Rust-сборка читает
этот JSON в `build.rs` и генерирует свои константы. Тест в TS и тест в Rust оба проверяют, что их
таблицы совпадают с JSON. Расхождение становится красным тестом, а не загадкой в чужом терминале.

## 5. Именованные гранты (Б-2)

Проблема: гранты умирают с окном — это и есть вся история отзыва (`grantRegistry.ts` — карта в
памяти). Имя же должно жить дольше.

Предложение, не ломающее модель отзыва:

- В расширении — новая команда **`Enable CLI Access…`** на записи: она даёт записи **имя-псевдоним**
  (по умолчанию slug от имени записи) и сохраняет **только имя → `(accountId, entityId, kind)`** в
  `globalState` (пломбированном с 0.57.0). **Секрета там нет и токена там нет.**
- `creds ssh prod-db` идёт не с токеном, а с **именем**. Новый маршрут брокера
  `POST /v1/grant` с телом `{alias}`: сервер ищет псевдоним, **минтит свежий грант на месте** и
  выполняет запрошенное действие в том же вызове. Согласие — как обычно: первый вызов открывает
  модал.
- То есть токен вообще перестаёт путешествовать по буферу обмена для CLI-пути. Псевдоним — не
  секрет; способность им воспользоваться даёт только живое окно + согласие человека.
- **Порт всё ещё нужно найти.** Здесь появляется единственный новый файл на диске:
  `<globalStorage>/cli-endpoint.json` c `{port, pid, startedAt}`, права 0600 через уже существующий
  `lockToOwner` (`materializedKeys.ts`). Пишется при старте брокера, удаляется в `dispose`.
  Файл **не содержит секрета** — только порт; аутентификация остаётся согласием человека, а
  `/v1/health` по-прежнему проверяется до всего остального.
  Если файлов несколько (несколько окон) — CLI показывает выбор или берёт по `--window`.

Это осознанное расширение модели доверия: раньше «кто держит токен, тот и может» (в пределах окна),
теперь для CLI-пути — «кто может писать в мой globalStorage и присутствует у экрана». Второе не
слабее: и то и то требует локального пользователя, а согласие человека остаётся обязательным.

## 6. Форма команд

```
creds ls                          # псевдонимы, включённые для CLI
creds ssh <alias> [-- cmd…]       # exec, либо интерактивный терминал в VS Code без --
creds run <alias>                 # сохранённая команда
creds script <alias>              # сохранённый скрипт
creds db <alias> -- "select 1"
creds env <alias>                 # печатает ИМЕНА переменных, не значения
creds vpn up|down <alias>
creds doctor                      # какие окна найдены, отвечает ли health, версия контракта
```

Коды выхода — ровно те же 90–99 плюс проброс кода удалённой команды. `creds doctor` существует
потому, что «ничего не работает» у CLI имеет пять разных причин (окно закрыто, порт занят чужим,
контракт разошёлся, псевдоним не включён, согласие не получено), и человек должен их различать.

## 7. Порядок сборки

0. **Починить Б-1** (`agentCli.ts`: форматтер ответа на глагол) + тесты. Отдельный маленький PR,
   не ждёт остального.
1. `contract/broker-v1.json` + генератор из `brokerProtocol.ts` + TS-тест на совпадение.
2. Реестр псевдонимов: `cliAliases.ts` (чистый), команда `Enable CLI Access…`, `Disable…`, хранение
   в `globalState`, тесты.
3. `POST /v1/grant` (минт по псевдониму) + `cli-endpoint.json` (запись/удаление/0600) + тесты
   брокера.
4. `src_cli_rust/`: аргументы, чтение endpoint-файла, health-проба, HTTP, коды выхода, `doctor`;
   `build.rs` из JSON-контракта; unit-тесты + тест на совпадение таблиц.
5. Интеграционный тест: расширение (стаб `vscode`) + настоящий Rust-бинарь, как это уже делает
   `agent-broker-itest.cjs` для node-версии. В CI — сборка бинаря под три платформы.
6. Документация: README (раздел CLI), `module_extension.md`, установка (`cargo install`/архивы в
   GitHub release рядом с `.vsix`).

## 8. План тестирования

- Б-1: красный тест на каждый из трёх глаголов (`env`, `vpn-up`, `vpn-down`) — успех печатает
  результат и выходит 0.
- Контракт: TS-таблица == JSON == Rust-таблица (два теста, по одному в каждом языке).
- Псевдонимы: включение/выключение; **в `globalState` нет ни токена, ни секрета** (grep-тест по
  сериализованному состоянию); неизвестный псевдоним → 404, а не намёк на существование.
- Endpoint-файл: создаётся при старте, удаляется при dispose, права 0600, при двух окнах CLI
  сообщает о выборе; **устаревший файл** (pid мёртв) не приводит к попытке отправить что-либо.
- Health-проба обязательна: подложить на порт чужой сервер — CLI должен отказаться, не отправив
  ничего.
- Согласие: первый вызов через CLI открывает модал; отказ → код 92; таймаут → 97.
- E2E: `creds ssh <alias> -- echo hi` через настоящий бинарь и настоящий брокер.

## 9. Definition of Done

- [ ] Б-1 исправлен и покрыт тестом (независимо от остального плана).
- [ ] Один источник истины для контракта; расхождение TS↔Rust — красный тест.
- [ ] `creds` работает при закрытом окне? **Нет — и это документировано явно**: закрытое окно
      означает «нет согласия и нет ключей», CLI печатает это одной фразой, а не «connection refused».
- [ ] В реестре псевдонимов никогда не лежит секрет; endpoint-файл содержит только порт/pid.
- [ ] Бинари для win/mac/linux собираются в CI и прикладываются к релизу.
- [ ] README + `module_extension.md` описывают модель доверия CLI-пути честно (см. §5).

   `ssh:terminal`) или пробовать интерактив в текущем терминале? Второе требует проброса TTY и, по
   сути, превращается в задачу плана
   [PLAN_remote_broker_bridge.md](PLAN_remote_broker_bridge.md). Предложение: пока первое.
2. Нужен ли `creds --json` для машинного чтения (для скриптов и других агентов)?
3. Ставить ли алиас `creds` автоматически из расширения (команда *Install CLI*), или только
   документировать ручную установку? (Автоматически — это запись в системный PATH, требует
   отдельного согласия.)
