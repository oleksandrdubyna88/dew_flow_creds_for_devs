## Почему это важнее, чем кажется

Расширение уже полностью готово к публикации механически: `.vsix` собирается, метаданные
проставлены, `docs/PUBLISHING.md` описывает процедуру. Не хватает ровно одного — человек, попавший
на страницу, **не видит, как это выглядит**. Для менеджера паролей это решающий кадр: категория
переполнена, и выбирают глазами за три секунды.

## Главное правило: все данные должны быть выдуманными

**Не «тестовый аккаунт», а придуманные с нуля.** Скриншот менеджера паролей — это скриншот чьей-то
инфраструктуры, и после публикации он индексируется навсегда.

| нельзя | можно |
|---|---|
| `10.73.48.167` | `10.0.0.12`, `db-01.example.internal` |
| `alert-center-production-mysql.c0h8c2a0sivu.us-east-1.rds.amazonaws.com` | `db-01.example.internal` |
| `oleksandr.dubyna@remsoft.dev` | `dev@example.com`, `ops@example.com` |
| `mysql://oleksandr_dubyna:f3gE4Zxa…@…` | `mysql://app:••••••@db-01.example.internal:3306/orders` |
| настоящие имена папок и записей | `prod`, `staging`, `orders-db`, `bastion` |

Проверить перед публикацией: открыть каждый PNG и прочитать **весь текст на нём**, включая серые
приписки справа от строк дерева и подсказки под полями — именно там прячутся хосты.

## Как готовить хранилище для съёмки

Снимать из рабочего профиля нельзя — там ваши настоящие данные. Отдельный профиль VS Code даёт
пустой `SecretStorage` и чистое дерево:

```bash
code --profile shots
```

Установить туда `.vsix`, завести один-два выдуманных аккаунта и примерно такой набор:

```
dev@example.com
├── ssh connections
│   ├── bastion            ops@bastion.example.internal
│   ├── app-01             app@10.0.0.21
│   └── app-02             app@10.0.0.22
├── ssh keys
│   └── deploy key
├── db
│   └── orders-db          mysql
├── vpn
│   └── office vpn         openvpn
└── passwords
    └── grafana admin

ops@example.com
└── (второй аккаунт нужен только чтобы на кадре было видно, что их может быть несколько)
```

Для `depends-on.png` дополнительно: у `app-01` и `orders-db` поставить зависимость от `office vpn`
— тогда все три записи будут одного цвета, а у `office vpn` раскроется «Depended on by 2».

**Этот же профиль закрывает второй пункт DoD плана** — «пройти quickstart из README как новый
пользователь в чистом профиле». Пройдите его один раз перед съёмкой и запишите, если что-то в
инструкции не сходится с реальностью.

## Три ловушки

**1. Marketplace не отображает относительные пути к картинкам.** Ссылки в README должны быть
абсолютными raw-GitHub URL:

```markdown
![Дерево](https://raw.githubusercontent.com/oleksandrdubyna88/dew_flow_creds_for_devs/main/src_vs_code/media/docs/tree.png)
```

По словам плана, относительный путь — самый частый способ отгрузить листинг с битыми картинками.

**2. Картинки не должны попасть в `.vsix`.** Сейчас `.vscodeignore` не исключает `media/`, значит
`media/docs/**` уедет в пакет и раздует его на несколько мегабайт без всякой пользы — Marketplace
всё равно берёт их по URL. Нужно добавить `media/docs/**` в `.vscodeignore` и проверить:

```bash
npx vsce ls --tree
```

**3. Таблицы в README широкие и плохо переносятся** на ширине Marketplace. Перед публикацией
посмотреть предпросмотр именно в этой ширине, а не в редакторе.
