## 0. Откуда это взялось

Четыре независимых прохода по коду 2026-08-25: архитектурный (`src_vs_code/src`, 95 модулей +
71 тестовый файл), безопасность/синк/брокер (с оглядкой на whitepapers 1Password, Bitwarden,
KeePassXC, Proton), UX и поверхность функций (глазами пользователя 1Password / Termius / Royal TS /
Remote-SSH), и сравнение с рынком (менеджеры паролей, менеджеры SSH-подключений, секрет-менеджеры
для разработчиков, VS Code Marketplace, «агент использует секрет, не видя его»).

**Уже закрыто в 0.56.1** — единственная находка уровня HIGH: `psql -c '\! echo $PGPASSWORD'` был
синтаксически валидным «запросом», чей stdout — пароль, возвращённый агенту без повторного согласия
(согласие — на грант, не на запрос). Закрыто `refuseQuery()` в `dbCliLauncher.ts`; красный тест
видели падающим по настоящей причине.

## 2. Где мы уже на уровне лучших — не трогать при рефакторинге

- **Правило «без `vscode`»** соблюдено реально: 69 из 95 модулей чистые, транзитивных утечек нет;
  `resolveSshCredential` одинаково служит человеку и брокеру.
- **Крипто**: AES-256-GCM со свежим IV на вызов; параметры scrypt записаны в блоб — понижение стоимости
  ломается на auth-теге, а не на эвристике (`cryptoUtils.ts:51-60, 125-131`); HKDF с разделением
  доменов; слоты ключей по образцу LUKS; обнуление ключей с юнит-тестом на анти-алиасинг
  (`vaultKeyLifetime.ts`); PIN-политика, считающая офлайн-атаку, а не копирующая NIST.
  Многослотовая разблокировка WebAuthn-PRF на **локальном файле** — этого нет ни у кого из сравнения.
- **Синк** причинный (векторы версий + горизонт тумбстоунов), условная запись под тем же локом, что и
  проверка (`VaultStore.cs:62-101`), кэш расшифровки по хэшу байтов.
- **Сервер**: ресурс всегда выводится из проверенного токена, никогда из запроса — IDOR структурно
  невозможен (`Program.cs:326-341`); контейнер: uid 10001, read-only rootfs, без capabilities, chiseled.
- **Брокер** структурно сильнее любого `op run`/`bws run`/Warp: секрет едет в процессе, порождённом
  расширением, у агента нет `printenv`. Локально SSH/DB/VPN/скрипты так не брокирует никто.
- **Мультивыбор** (`selectionResolver.ts`) корректно обходит реальное ограничение API VS Code («when»
  вычисляется по якорной строке); `contextValue` как строка возможностей вместо lookahead-регексов.

### D. Новые функции — по убыванию ценности

Каждая — отдельный `todo/PLAN_*.md` при старте; здесь — ТЗ и точки опоры в коде.

**D1. SSH-агент с подтверждением на использование + подпись Git-коммитов.** Опора: `keyInstaller.ts`,
`materializedKeys.ts`, `sshCredential.ts`. Режимы: собственный сокет (`SSH_AUTH_SOCK`) или загрузка в
работающий агент с временем жизни; на каждое использование — модал/тост «ключ X запрошен процессом Y»
(как 1Password); ключ не ложится на диск вовсе. `gpg.format ssh` — «Copy signing config».

**D2. TOTP.** Поле `otpauth://` (секрет — в SecretStorage), код во вьюере с таймером, Copy; Steam-вариант
по желанию. Опора: `entityViewPanel.ts` (копия по полю), `secretClipboard.ts` (TTL).

**D3. Ссылки на секреты + обёртка `run` с маскированием.** `creds://<account>/<entity>/<field>` в
скриптах/командах; `CredsForDevs: Run with secrets` резолвит в env дочернего процесса и **маскирует**
значения в stdout/stderr терминала (как `op run`). Опора: `scriptRender.ts` (`resolveScriptEnv`,
`detectSecretPrints`), `envBinding.ts`. Закрывает утечку через `echo`, которую README признаёт, и делает
глагол `env` брокера ненужным.

**D4. Импорт.** `~/.ssh/config` (Host/HostName/User/Port/IdentityFile/ProxyJump → SSH-сущности и ссылка на
ключ), KDBX (KeePass), экспорт Bitwarden/1Password (JSON/CSV), Termius. Опора: `externalBundle.ts`,
`shareFormat.ts` (`Import from External…`). Импорт — единственный путь снизить стоимость перехода.

**D5. Генератор** паролей / парольных фраз / ключей Ed25519 в форме (`entityFormPanel.ts`, поле
Password и `keySection`). Ключ — сразу в SecretStorage, без файла.

**D6. Отчёты о гигиене** (локально, opt-in): слабые/повторяющиеся пароли (zxcvbn), незашифрованные ключи
в `~/.ssh`, `.env` в открытом виде в workspace, HIBP по k-анонимности (сеть — только по явному
включению; принцип «без сети по умолчанию» README сохраняется). Опора: `pinPolicy.ts` (оценка).

**D7. Поля менеджера подключений на SSH-сущности:** jump host как ссылка на другую сущность (механизм

## 5. План тестирования

- Каждая правка — по правилу репо: RED-тест первым, падение по настоящей причине записано в коммит.
- A1: набор до и после разбора идентичен по количеству и зелёный; новые модули — свои тесты.
- A2: намеренное нарушение (`max-lines-per-function`) в ветке — CI красный.
- A4: тип-тест `never` на новый род; миграционный тест на запись без `kind`; тест совпадения
  `:ssh`/`kindOf`.
- A5: подделанный заголовок → исключение из `decipher.final()`; старый v3 читается.
- C1–C4: тесты с подсчётом вызовов зависимостей (0 обращений к `getPassword` при раскрытии; 1 парсинг
  на N чтений; idle-цикл без `fingerprint`).
- D-фичи: у каждой — «секрет не появляется там, где не должен» как первый тест (в логе, в argv, в
  метаданных, в ответе брокера).
