## Подготовка (5 минут)

**1. Расширение.** Установлено 0.78.1 — проверить: `Ctrl+Shift+P` → *Extensions: Show Installed*,
CredsForDevs, версия 0.78.1. Окно перезагрузить (`Developer: Reload Window`).

**2. Бинарь.** Уже собран:

```
D:\rsd\dew_flow_creds_for_devs\src_mcp\src\bin\Debug\net10.0\creds-mcp.exe
```

Если нет — `dotnet build src_mcp/src/CredsMcp.csproj`.

**3. Подключить его к Claude Code.** В `~/.claude.json` (или `.mcp.json` в проекте):

```json
{ "mcpServers": { "creds": { "command": "D:\\rsd\\dew_flow_creds_for_devs\\src_mcp\\src\\bin\\Debug\\net10.0\\creds-mcp.exe" } } }
```

Перезапустить Claude Code. `/mcp` должен показать `creds` и восемь инструментов.

> **Кнопку «Install the MCP Server…» пока проверить нельзя** — тега `mcp-v*` ещё нет, релиза не
> существует. Это последний пункт списка, и он ждёт тега.

**4. Подопытная запись.** Завести SSH-запись на хост, куда вы ходите **по ключу** — папка
«Servers», имя `mcp-test`. Поле пароля не заполнять или заполнить мусором: его будет ротировать
пункт 4, и на вход по ключу это не влияет. **Не берите продовую запись.**

## 1. Пока не включено — не видно ничего

| Делаем | Должно быть |
|---|---|
| Спросить агента: «какие у меня есть доступы?» | `creds_list` вернул **пустой список** и агент говорит, что ничего не открыто |

## 2. Лестница и наследование

1. Правый клик по `mcp-test` → **Edit** → секция **Agent access**. Все шесть выключены.
2. Включить **Usable by agents**. Смотреть: *Visible to agents* включился **сам** и заблокировался.
3. Save. Спросить агента снова.

| Должно быть |
|---|
| Запись видна. В ответе есть `host`, `user`, `port`, **нет** пароля. `can.use = true`, `can.edit = false` |

4. Правый клик по папке **Servers** → **Edit** → включить **Visible to agents** → Save.
5. Завести в ней вторую запись, ничего ей не включая. Спросить агента.

| Должно быть |
|---|
| Вторая запись тоже видна — она унаследовала настройку папки |

**Баг, если**: удалось выключить *Visible* при включённом *Usable*; или наследование не сработало;
или в ответе оказался пароль.

## 3. Использование — и то, что спрашивают каждый раз

Попросить: «выполни `uname -a` на mcp-test».

| Должно быть |
|---|
| В VS Code всплыло окно: **Claude Code хочет run a command on «mcp-test»** и **сама команда** |
| Нажать **Allow** → агент получил вывод |
| Повторить ту же просьбу → окно всплыло **снова** |

**Баг, если**: второй раз не спросили. Переключатель говорит «спрашивать можно», окно — «этот вызов
происходит», каждый раз.

Теперь **Deny** на третьей попытке → агент получает отказ, команда не выполняется.

## 4. Ротация — и главная проверка этого релиза

Попросить дословно:

> выполни creds_rotate для mcp-test со statement: `echo '{{creds:new}}'`

| Должно быть |
|---|
| Окно согласия показывает статью **с `{{creds:new}}` внутри**, а не со значением |
| После Allow агент отвечает `"rotated": true` |
| **В выводе на месте секрета — `<CREDS_MASKED:PASSWORD>`**, а не сам пароль |
| Правый клик по записи → в дереве появилась/выросла история версий |

**Это главная проверка.** `echo` печатает то, что ему дали, — то есть только что сгенерированный
пароль. Если агент увидел его открытым текстом, значит маскировщик не сработал: это ровно тот
дефект, который нашли и починили в 0.76.0.

**Баг, если**: в окне согласия виден настоящий пароль; или в ответе агента виден настоящий пароль;
или история версий не выросла.

Попробовать ещё: `creds_rotate` со `statement: "true"` (без плейсхолдера) → **отказ** с объяснением,
что нужен `{{creds:new}}`. Ничего не выполнилось, ничего не записалось.

## 9. Показать запись по id

| Должно быть |

## 10. Значки в дереве — посмотреть глазами

Глядя на дерево после пунктов 2–6:

- У записей с включённым доступом под значком **пять полосок**; горят столько, сколько ступеней
  включено, слева направо: зелёная → голубая → янтарная → фиолетовая → красная.
- У записей **без** доступа значок обычный, как у VS Code, — полосок нет вовсе.
- Переключить тему (светлая ↔ тёмная) — полоски читаются в обеих.

**Смотреть придирчиво**: глифы для записей с доступом рисуем мы, а не редактор. Если они выбиваются
из набора VS Code сильнее, чем терпимо, — это стоит сказать.

## 12. Из WSL — пройдено 2026-08-28

Мост реализован ([../research/PLAN_mcp_wsl_bridge.md](../research/PLAN_mcp_wsl_bridge.md)), и этот
проход сделан на настоящем Claude Code внутри дистрибутива Ubuntu против окна VS Code 0.80.7 на
Windows. Как подключено:

```bash
# Linux-бинарь (framework-dependent, dotnet 10 в дистрибутиве уже есть)
dotnet publish -c Release -r linux-x64 --self-contained false -p:PublishAot=false   -o ~/.local/share/creds-mcp                      # из чистой копии исходников в /tmp

claude mcp add -s user creds   -e CREDS_MCP_WINDOWS_BINARY=/mnt/d/rsd/dew_flow_creds_for_devs/src_mcp/src/bin/Debug/net10.0/creds-mcp.exe   -- ~/.local/share/creds-mcp/creds-mcp
```

| Проверено | Результат |
|---|---|
| `claude mcp list` | `creds ✔ Connected` |
| `creds_list` через настоящего агента | вернул запись из хранилища на Windows, с `can`, без секрета |
| `creds_create` (оба пути: `secretKind` и свой `secret`) | **отказ до всякого окна согласия** — см. находку ниже |

**Находка, требующая решения владельца.** `creds_list` отдаёт записи `can.create: true`, а
`creds_create` отвечает *«No folder is open to agents for creating entries»* и никого не спрашивает.
Противоречия в коде нет: `capabilitiesOf` строит `can.create` из переключателя **записи** (своего или
унаследованного от папки), а `creatableFolders` требует переключатель **самой папки**
(`opensToCreation`, папки создание не наследуют — это записано намеренно). Но агенту это читается как
разрешение, которого нет: он планирует создание, тратит вызов и получает отказ. Отказ хороший и
называет переключатель. Варианты: считать `can.create` от папки, а не от записи; или убрать поле из
листинга записей, раз оно про папку. Не трогал — это изменение видимого агентам контракта.

**Чтобы пройти пункт 5 из WSL**, нужно включить *Agents may create entries* на самой папке
(правый клик по папке → Edit → Agent access), а не только на записи.
