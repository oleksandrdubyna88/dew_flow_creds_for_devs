## Проблема

Расширение умеет то, чего не умеет почти никто: **агент может воспользоваться доступом, не получив
его**. Он не видит пароль, не видит приватный ключ — он просит «выполни вот эту команду на вот этом
хосте», человек один раз подтверждает, команда выполняется, агент получает вывод с вымаранными
секретами.

Проблема в том, **как агент об этом узнаёт**. Сейчас — никак. Человек должен скопировать из UI
сниппет вида `node agentCli.js …` и вставить агенту в контекст. Все конкуренты в этой категории
показывают себя агентам через MCP: клиент сам спрашивает у сервера список инструментов и их
описания, и агент знает о возможностях с первой секунды.

То есть **обнаружимость — это и есть вся задача D8.** Механика «использовать, не выдавая» уже
работает и переписыванию не подлежит.

## Часть 1. Что у нас есть — инвентаризация кода

### 1.1. Глаголы брокера (`useActions.ts` + регистрация в `extension.ts:608-636`)

Реестр пар `(вид сущности, действие)`. Сегодня зарегистрировано восемь:

| пара | что делает | куда девается секрет |
|---|---|---|
| `(ssh, exec)` | выполняет команду на хосте | ключ/пароль в ssh-агент или во временный файл, агенту не виден |
| `(ssh, terminal)` | открывает человеку подключённый терминал | то же |
| `(script, run)` | запускает скрипт | в окружение дочернего процесса |
| `(terminal, run)` | запускает сохранённую команду | секрета нет вовсе |
| `(db, query)` | выполняет SQL | `PGPASSWORD` / `MYSQL_PWD` / `SQLCMDPASSWORD`, **никогда не в argv** |
| `(credential, exportEnv)` | выставляет переменные окружения | отвечает **только именами**, не значениями |
| `(vpn, up)` / `(vpn, down)` | поднимает/опускает VPN | конфиг материализуется во временный файл |

Всё это уже проходит через: проверку тела запроса → диалог согласия у человека → выполнение →
маскирование вывода → строку в аудит-файл. **MCP не добавляет сюда ничего — он это показывает.**

### 1.2. Что брокер сейчас НЕ отдаёт, а мог бы

| источник | что там есть |
|---|---|
| `treeSearch.ts` | поиск по дереву с железной гарантией «никогда по секретам» — есть тест, что ни одно секретное поле недостижимо ни одним запросом |
| `depGraph.ts` | **зависимости между записями** — сделаны сегодня, в брокере не представлены вообще |
| `hygiene.ts`, `hygieneScan.ts` | отчёт о здоровье: переиспользованные и слабые пароли, незашифрованные ключи, `.env` в открытом виде |
| `entityExpiry.ts` | сроки жизни: что скоро протухнет, что удалится после первого использования |
| `totp.ts` | одноразовые коды |
| `secretGenerator.ts` | генерация паролей, парольных фраз и ключей Ed25519 |

### 1.3. Где уже написан клиент брокера

`src_cli/` — .NET Native AOT бинарь `creds`, и в нём уже есть `BrokerClient.cs`,
`BrokerContract.cs`, `GrantToken.cs`, `Endpoints.cs`, `WslInterop.cs`. Глаголы сегодня:
`ssh`, `exec`, `run`, `db`, `env`, `terminal`, `relay`, `help`. **`mcp` среди них нет.**

### 1.4. Ограничение, которое определяет архитектуру

У расширения **ноль рантайм-зависимостей** — это осознанное решение, записанное в

нельзя). Официальный MCP SDK для Node был бы **первой рантайм-зависимостью** в истории проекта.

## Часть 2. Что можно отдать в MCP — по пунктам, с примерами

Ниже каждый пункт — это один инструмент, который агент увидит в списке. Формат: что агент
спрашивает → что происходит → что он получает.

### Группа А. Только чтение. Секретов не касается вообще

#### A1. `creds_list` — какие доступы вообще есть

> **Агент:** «Какие у меня есть подключения?»
> **Инструмент возвращает:** список записей — имя, вид, папка, аккаунт. Хост и пользователь — да.
> Пароль, ключ, строка подключения — **никогда**.
>
> ```json
> [
>   { "name": "app-01", "kind": "ssh", "folder": "ssh connections", "target": "app@10.0.0.21" },
>   { "name": "orders-db", "kind": "db", "folder": "db", "target": "mysql" }
> ]
> ```

Опора: `nodeHaystack` из `treeSearch.ts` — ровно тот текст, который строка дерева и так показывает
вслух. Гарантия «если строка этого не говорит, то и найти этого нельзя» уже покрыта тестом.

**Важно, и об этом отдельный разговор ниже:** у CLI команды `ls` **нет намеренно** — это записано
в `PLAN_cli_bridge_tail.md` как живая защита. Здесь модель угроз другая, но решение всё равно за
владельцем.

#### A2. `creds_describe` — что это за запись

> **Агент:** «Расскажи про `app-01`.»
> **Возвращает:** вид, хост, пользователь, порт, теги, есть ли пароль (**да/нет**, не значение),
> есть ли одноразовый код, срок жизни, **от чего запись зависит**.

#### A3. `creds_dependencies` — что нужно поднять, прежде чем это заработает

Это самый полезный для агента пункт из всего списка, и он появился только сегодня.

> **Агент:** «Хочу выполнить команду на `app-01`. Что-нибудь нужно сделать заранее?»
> **Возвращает:** `app-01` зависит от `office vpn` (вид: vpn, сейчас не поднят).
>
> Дальше агент сам понимает, что сначала надо вызвать `creds_vpn_up`, а потом `creds_ssh_exec` —
> вместо того чтобы получить таймаут подключения и гадать.

Сегодня эта связь видна только человеку в дереве по цвету. Агенту она не видна никак.

#### A4. `creds_health` — отчёт о гигиене

> **Агент:** «Проверь, всё ли в порядке с доступами.»
> **Возвращает:** переиспользованные пароли, слабые пароли, приватные ключи без парольной фразы,
> найденные в проекте `.env` с секретами в открытом виде.

Опора: `hygiene.ts` / `hygieneScan.ts` — отчёт уже есть, у него просто нет выхода наружу.

#### A5. `creds_expiring` — что скоро протухнет

> **Агент:** «Что просрочится на этой неделе?»
> **Возвращает:** записи со сроком жизни и оставшимся временем.

### Группа Б. Действие без выдачи секрета — уже существующие глаголы

#### B1. `creds_ssh_exec` — выполнить команду на хосте

> **Агент:** «Выполни `docker ps` на `app-01`.»
> **Что происходит:** человек видит диалог «Claude Code хочет выполнить команду на app-01:
> `docker ps`» → подтверждает → команда выполняется → агент получает stdout с **вымаранными**
> секретами.
>
> Ключ агенту не передаётся ни в каком виде.

#### B2. `creds_ssh_terminal` — открыть человеку терминал

> **Агент:** «Открой мне терминал на `app-01`.»
> **Что происходит:** открывается терминал VS Code, уже подключённый. Агент не получает ничего,
> кроме подтверждения, что открылось. Это намеренно: терминал — для человека.

#### B3. `creds_db_query` — выполнить SQL

> **Агент:** «Посчитай заказы за сегодня в `orders-db`.»
> **Что происходит:** пароль уходит в переменную окружения дочернего процесса — **никогда в
> командную строку**, потому что argv виден всем в списке процессов. В командной строке только
> хост, порт и имя базы.
>
> MongoDB отказано намеренно: у `mongosh` нет переменной окружения для пароля, а его `--eval`
> исполняется в том же интерпретаторе, который умеет читать `process.env` — то есть «запрос»
> агента мог бы напечатать пароль обратно.

#### B4. `creds_vpn_up` / `creds_vpn_down`

> **Агент:** «Подними `office vpn`.»
> **Что происходит:** конфиг материализуется во временный файл, VPN поднимается в терминале
> человека — потому что безголовый процесс не сможет ответить на запрос прав администратора.

#### B5. `creds_run` — запустить сохранённую команду или скрипт

> **Агент:** «Запусти `aws sso login`.»
> **Что происходит:** запускается ровно то, что сохранено, — с примечаниями к каждому аргументу,
> которые человек когда-то записал.

#### B6. `creds_export_env` — выставить переменные окружения

> **Агент:** «Дай мне доступ к базе для терраформа.»
> **Возвращает:** список **имён** переменных, которые были выставлены. Не значения. Текст
> согласия так и говорит.

### Группа В. Чего в MCP быть не должно — никогда

| нельзя | почему |
|---|---|
| прочитать пароль, приватный ключ, строку подключения, seed одноразового кода | это ровно та выдача, которой продукт существует, чтобы не происходить |
| выгрузить хранилище, снять бэкап, прочитать бэкап | одна операция вместо тысячи |
| удалить запись, удалить папку, удалить аккаунт | необратимо, и агент не тот, кто должен это решать |
| сменить место синхронизации, снять пин с host key | тихо ломает границу доверия |
| прочитать историю версий | это старые пароли, они пароли и есть |

Генерацию секретов (`secretGenerator.ts`) сознательно **не** включаю в первую версию: сгенерировать
пароль — значит его показать, а показать его агенту незачем; пусть человек нажмёт кнопку в форме.

## Часть 3. Где должен жить MCP-сервер

Это главное архитектурное решение, и очевидный ответ — неправильный.

### Вариант 1 — внутри расширения (отвергается)

Расширение поднимает stdio-сервер MCP. Проблемы: понадобится либо официальный SDK (**первая
рантайм-зависимость за всю историю проекта**), либо руками написанный JSON-RPC. И главное —
расширение живёт внутри VS Code, а MCP-клиент запускает сервер как **свой дочерний процесс**; это
принципиально не то время жизни.

### Вариант 2 — режим существующего CLI (рекомендую)

Новый глагол `creds mcp`, поднимающий stdio-сервер MCP. Он переиспользует всё, что уже написано:

- `BrokerClient.cs` — клиент брокера,
- `GrantToken.cs` — гранты,
- `Endpoints.cs` — поиск живого окна VS Code,
- `WslInterop.cs` — работа из WSL «из коробки».

Расширение при этом **не меняется вообще** и не получает ни одной зависимости. MCP-клиент
настраивается одной строкой:

```json
{ "mcpServers": { "creds": { "command": "creds", "args": ["mcp"] } } }
```

.NET-сторона может взять официальный `ModelContextProtocol` NuGet — это ровно то, что делает
`dew_flow_mcp`, то есть в семье уже есть работающий образец (`src/Mcp.Server/`,
`src/Mcp.Application/ToolCatalog.cs`).

### Вариант 3 — отдельный сервер (отвергается)

Третий бинарь, третье место, где нужно чинить одну и ту же ошибку.

## Часть 4. Порядок сборки

1. **Контракт списка инструментов — сначала, как данные.** Один каталог (имя, описание, схема
   аргументов, к какому глаголу брокера сводится) — по образцу `ToolCatalog.cs` из `dew_flow_mcp`.
   Тест: каждый инструмент каталога сводится к существующему `(вид, действие)` или к
   существующему read-only источнику; ни одного «висячего» инструмента.
2. **Группа А, только чтение.** `creds_list`, `creds_describe`, `creds_dependencies`,
   `creds_health`, `creds_expiring`. Требует новых read-only маршрутов у брокера — их сегодня нет.
   Здесь же тест: **ни один ответ группы А не содержит ни одного секретного поля** — по образцу
   `treeSearch.test.ts`, который уже доказывает это для фильтра дерева.
3. **Группа Б, действия.** Каждый инструмент — тонкая обёртка над уже существующим
   `POST /v1/use/<действие>`. Новой логики согласия, маскирования и аудита не пишется вовсе.
4. **`creds mcp` как глагол CLI**, stdio-транспорт, каталог из шага 1.
5. **Команда в расширении**: *Set Up MCP Access…* — показывает готовый JSON для конфига клиента и
   объясняет, что даёт и чего не даёт.
6. **Интеграционный тест**, по образцу `scripts/creds-cli-itest.cjs`: реальный stdio-обмен,
   `tools/list` возвращает каталог, `tools/call` доходит до брокера, отказ выглядит как отказ.
7. Документация: `research/module_extension.md`, README, changelog.

## Часть 5. Тест-план

| что | чем проверяется |
|---|---|
| каталог не содержит инструмента без реализации | тест каталога |
| ни один read-only ответ не отдаёт секретного поля | тест по образцу `treeSearch.test.ts` |

| контракт CLI ↔ брокер не разошёлся | `npm run contract` уже существует |

## Часть 6. Риски

1. **Обнаружимость — это и фича, и поверхность атаки.** Список инструментов + `creds_list` даёт
   перечисление всего хранилища. Именно поэтому у CLI намеренно нет `ls`. Модель угроз здесь
   другая: MCP-сервер запускается агентским клиентом самого пользователя, а не безымянным сетевым
   вызовом. Но это надо решить сознательно, а не по умолчанию — вопрос 1 ниже.
2. **Второй клиент делает срочным версионирование контракта** — это прямо записано в пункте E3
   дорожной карты.
3. **Согласие на каждый вызов утомляет.** У брокера уже есть гранты с временем жизни; для MCP
   стоит проверить, что «подтвердил один раз на сессию» не превращается в «подтвердил навсегда».
4. **Отсутствующий `creds` в PATH** — самая частая причина, по которой MCP-сервер «не работает», и
   диагностика должна это называть прямо, а не молчать.

## Часть 7. Решения, которые нужны от владельца

1. **Объём (это и есть незакрытый вопрос D8 из дорожной карты).** Только группа Б (действия,
   которые уже есть) — или ещё и группа А (чтение состояния)? Группа А делает агента куда
   полезнее и одновременно даёт ему перечисление хранилища.
2. **`creds_list` — да или нет?** Прямо противоречит осознанному решению «у CLI нет `ls`».
   Компромисс: список только тех записей, у которых включён CLI-алиас, — тогда перечисление
   ограничено тем, что человек сам разрешил.
3. **Политика на команду** (regex на ssh-команду, read-only SQL, белый список глаголов) — в этой
   задаче или отдельной? В дорожной карте она записана в тот же пункт D8.
4. **Куда идёт `creds mcp` по умолчанию**, если живых окон VS Code несколько? У CLI эта проблема
   уже решена через `Endpoints.cs`; надо только подтвердить, что для MCP поведение то же.

## Definition of Done

- [ ] Каталог инструментов — данные, а не код, и покрыт тестом на «нет висячих инструментов».
- [ ] Ни один read-only ответ не содержит секретного поля, и это тест, а не обещание.
- [ ] Действия — тонкие обёртки: ни одной новой строки согласия, маскирования или аудита.
- [ ] `creds mcp` работает из Windows и из WSL без настройки.
- [ ] Интеграционный тест гоняет реальный stdio-обмен.
- [ ] Расширение не получило ни одной рантайм-зависимости.
- [ ] `research/module_extension.md` и README описывают, что MCP даёт и чего не даёт.
- [ ] План промотирован в `research/` с записью отклонений.
