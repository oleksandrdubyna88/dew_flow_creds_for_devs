## Проблема

Расширение умеет то, чего почти никто не умеет: **агент может воспользоваться доступом, не получив
его**. Он не видит пароль и приватный ключ — он просит «выполни эту команду на этом хосте», человек
один раз подтверждает, команда выполняется, агент получает вывод с вымаранными секретами.

Не хватает двух вещей.

**Обнаружимость.** Сейчас человек копирует из UI сниппет и вставляет агенту в контекст. Конкуренты
показывают себя агентам через MCP: клиент сам спрашивает список инструментов, и агент знает о
возможностях с первой секунды.

**Управляемость.** Сегодня доступ — это всё или ничего на уровне грантов. Не выражается «пусть агент
видит, что у меня есть база заказов, но не трогает её» или «пусть подключается к стейджу, но не к
проду».

## Решение: пять переключателей на каждой записи

Новая секция **MCP** в форме редактирования, в дополнительной группе. **Все переключатели по
умолчанию выключены** — новая запись не видна агенту никак, пока человек этого не сделает.

Переключатели — **лестница**: каждый следующий включает предыдущий и блокирует его снятие.
Состояние «менять можно, а видеть нельзя» собрать невозможно — оно выглядит как опечатка и ничего
не означает.

| № | переключатель | цвет | что даёт |
|---|---|---|---|
| 1 | **виден** | зелёный | агент знает, что запись есть, и видит её несекретную часть |
| 2 | **можно пользоваться** | голубой | восемь готовых глаголов брокера; секрет не выдаётся |
| 3 | **можно обновлять секрет** | янтарный | перезаписать значение в существующей записи |
| 4 | **можно создавать** | фиолетовый | завести новую запись |
| 5 | **можно удалять — всё** | красный | отправить в корзину любую запись |
| 5 | **можно удалять — только своё** | красный | отправить в корзину только то, что агент создал сам |

Переключателей шесть, полосок в значке пять: **две галочки удаления делят один цвет и одну
полоску**. Это решение владельца, и оно правильное — в дереве важно «может ли агент здесь
удалять», а не «в каком именно объёме»; объём читается в форме.

Две галочки взаимоисключающие: «всё» включает «только своё» и гасит его.

Цвета берутся из той же палитры, что и зависимости (`depColors.ts`), и идут как эскалация от
безопасного к опасному. Зелёный и красный заданы владельцем, остальные три подобраны в этот ряд.

### Уровень 1 — «виден агенту»

Агент узнаёт, что запись существует, и видит её **несекретную** часть.

> **Агент:** «Какие у меня есть доступы к базам?»
> **Получает:**
> ```json
> { "id": "8f3a…", "name": "orders-db", "kind": "db", "folder": "db",
>   "dbType": "mysql", "host": "db-01.example.internal", "port": 3306,
>   "user": "app", "connectionString": "mysql://app@db-01.example.internal:3306/orders",
>   "notes": "основная база заказов", "hasPassword": true, "dependsOn": ["office vpn"] }
> ```

Пароль отсутствует, и **из строки подключения он вырезан**. Это не новый код: в `dbConnString.ts`
уже есть `withoutPassword()`. `hasPassword` говорит, что пароль есть, — но не какой.

**`id` и что с ним делать.** Ваше «вставлю в поиск, и оно подсветит запись» в текущем виде не
сработает: фильтр дерева ищет по `nodeHaystack` — имя, хост, юзер, порт, теги, — а идентификатора
там нет, и это правило, а не упущение («если строка не говорит этого вслух, найти это нельзя»).
Поэтому вместо поиска — команда **`CredsForDevs: Показать запись по id`**: вставили id, дерево
раскрылось до записи и подсветило её. Механика появилась сегодня — `getParent` написан, `reveal()`
работает.

### Уровень 2 — «можно пользоваться»

Включает то, что уже построено: агент вызывает действие, человек подтверждает, действие
выполняется, секрет агенту не передаётся. Восемь глаголов уже зарегистрированы
(`extension.ts:608-636`):

| глагол | что делает | куда девается секрет |
|---|---|---|
| `(ssh, exec)` | команда на хосте | ключ в ssh-агент, агенту не виден |
| `(ssh, terminal)` | терминал человеку | то же; агент получает только «открыто» |
| `(db, query)` | SQL | `PGPASSWORD` / `MYSQL_PWD`, **никогда не в argv** |
| `(script, run)` | скрипт | окружение дочернего процесса |
| `(terminal, run)` | сохранённая команда | секрета нет |
| `(credential, exportEnv)` | переменные окружения | отвечает **именами**, не значениями |
| `(vpn, up)` / `(vpn, down)` | VPN | конфиг во временный файл |

> **Агент:** «Посчитай заказы за сегодня.»
> **Человек видит:** «Claude Code хочет выполнить запрос к orders-db: `SELECT count(*) …`»
> **Агент получает:** результат. Пароля не видел.

Сюда же добавляется **одноразовый код** (`totp.ts`): агенту может понадобиться TOTP, чтобы
завершить вход. Это использование, а не просмотр.

### Уровень 3 — «можно обновлять секрет»

Строго одно: **перезаписать значение секрета в существующей записи.** Не менять хост, не трогать
настройки синхронизации, не создавать и не удалять — под это отдельные переключатели.

Это безопаснее, чем звучит, по причине, которая уже в коде: перед перезаписью снимается снимок в
историю версий, хранятся три предыдущих. Неудачная запись откатывается.

#### Ротация, при которой агент не видит ни старый пароль, ни новый

Загвоздка очевидна: чтобы выполнить `ALTER USER app IDENTIFIED BY '<новый>'`, надо знать новый.
Решение уже лежит в `secretRef.ts` — агент пишет **плейсхолдер**, подстановку делает расширение:

```
Агент:      ALTER USER app IDENTIFIED BY {{creds://orders-db/password}}
Расширение: сгенерировало новый пароль (secretGenerator.ts)
            → подставило в SQL → выполнило → записало новое значение в хранилище
            → сняло снимок старого в историю
Агент:      "готово, пароль ротирован"
```

Ни одного секрета в контексте агента, ни на входе, ни на выходе. Новой криптографии не требуется —
только соединение двух существующих механизмов.

**Генерирует расширение, всегда.** Решение владельца 2026-08-26: агент просит «сгенерируй такое-то»,
расширение генерирует и сохраняет, агент получает **ссылку**, а не значение, и вставляет ссылку
туда, где нужно значение. Подстановка происходит в момент выполнения, внутри расширения.

Что генератор умеет сегодня (`secretGenerator.ts`): **пароль**, **парольную фразу**, **ключ
Ed25519**. Этого хватает почти для всей ротации доступов — токен API это тот же случайный пароль с
другим набором символов.

Чего он не умеет: **сертификаты X.509**, **seed для TOTP**, **ключи RSA и ECDSA**.

**Что происходит в этом случае — решение владельца 2026-08-26: генерирует агент, и мы это
принимаем.** Расширение отвечает внятным отказом «я такое не умею», агент генерирует сам и
подставляет значение, расширение его сохраняет.

Это **сознательный размен, а не недосмотр**, и он должен быть записан как размен: для этих типов
секрет **проходит через контекст агента** — ровно то, чего вся остальная конструкция избегает.
Компенсирующая мера — журнал ниже: такие случаи в нём отдельная категория с отдельным фильтром,
чтобы «сколько секретов агент видел» был вопросом с ответом, а не предметом догадок.

Молчание или пустая строка в ответ на невыполнимую просьбу — недопустимо: агент подставит пустоту
в `ALTER USER` и сломает доступ, будучи уверен, что ротировал его.

## Журнал MCP

**Верхнее меню панели (⋯) → «MCP logs».** Показывает все вызовы через MCP: когда, какой инструмент,
какая запись, чем кончилось.

Два фильтра, и оба существуют ради конкретного вопроса:

| фильтр | отвечает на вопрос |
|---|---|
| **не смогли сгенерировать** | о чём нас просили и мы отказали — то есть где нам не хватает генератора |
| **сгенерировал агент и подставил** | **сколько секретов прошло через контекст агента** — цена размена выше, названная поимённо |

**Где это живёт.** Владелец сказал «не в файле, а в системе, чтобы я мог посмотреть» — то есть
журнал должен открываться в приложении, а не искаться на диске. При этом `agentAuditFile.ts` уже
пишет аудит в файл всегда, и это правильно: аудит, который можно потерять, закрыв окно, — не аудит.

Поэтому два разных предмета, и их не надо путать:

- **аудит** — на диск, всегда, как сейчас, без изменений;
- **журнал MCP** — представление в приложении поверх тех же событий, с фильтрами.

**Где лежит — там же, где уже лежат логи, и нового места не заводится.** `diagnosticLog.ts` пишет
в `globalStorageUri/logs/{день}/creds-{время}-{pid}.log` — это папка, которую VS Code выдаёт
расширению, и она следует семейной конвенции «папка на день, файл на запуск»
(`common/logging-serilog.md`):

```
Windows  %APPDATA%\Code\User\globalStorage\remsoftdev.creds-for-devs\logs\
Linux    ~/.config/Code/User/globalStorage/remsoftdev.creds-for-devs/logs/
macOS    ~/Library/Application Support/Code/User/globalStorage/remsoftdev.creds-for-devs/logs/
```

MCP-события пишутся туда же, отдельным источником, а «MCP logs» — **фильтрованное представление
над тем же файлом**. История между сессиями достаётся даром, второго хранилища не появляется, и
подметание старых запусков уже работает (две недели, папка дня уходит целиком).

Заводить для MCP отдельное место было бы ровно тем дрейфом, против которого правило о логах и
написано.

### Уровень 4 — «можно создавать»

Агент поднял сервер и сохраняет ключ сам, не отвлекая человека.

> **Агент:** «Я развернул `app-03`, сохрани ключ доступа к нему.»
> **Что происходит:** заводится новая запись в папке, назначенной для этого. Агент не выбирает
> место сам — иначе он выберет.

Операция добавляющая: неудачное создание удаляется вручную и ничего не разрушает.

### Уровень 5 — «можно удалять» — и корзина, которая делает это обратимым

Возражение против удаления было в том, что у него нет отката: оно расходится синком на все машины
и уносит историю версий. **Корзина снимает возражение целиком** — и меняет то, что означает слово
«удалить» во всём приложении.

**Корзина — папка на каждый аккаунт.** Удалённое переезжает в неё, а не исчезает. Восстановление —
это перемещение обратно, то есть механизм, который уже есть и уже синхронизируется.

| кто удаляет | что происходит |
|---|---|
| **агент через MCP** | **только в корзину**, всегда, без вариантов |
| **человек** | диалог: **[В корзину]** — кнопка по умолчанию, Enter нажимается не глядя — и **[Удалить навсегда]** |

`showWarningMessage(…, { modal: true }, 'В корзину', 'Удалить навсегда')` даёт ровно это: первая
кнопка срабатывает по Enter, Escape отменяет.

#### Корзина НЕ трогает `deleteNodeRecursive`, и это главное

`deleteNodeRecursive` — единственный путь удаления, и **три фичи зависят от того, что он удаляет
по-настоящему**: `burnOnUse.ts` (сгореть после одного использования агентом), `entityExpiry.ts`
(срок жизни) и `ephemeralSweeper.ts`. Их гарантия сформулирована в
[../research/PLAN_ephemeral_secrets.md](../research/PLAN_ephemeral_secrets.md) так: настоящее
удаление, когда время придёт — tombstone, все восемь ключей в keychain, история версий, — **никогда
не флаг, оставляющий секрет на месте**.

Встроить корзину внутрь этого метода значит: эфемерная запись, обещавшая самоуничтожиться, вместо
этого переезжает в папку и **остаётся рабочей**. Обещание нарушено молча.

Поэтому корзина — **отдельная операция уровнем выше**:

```
moveToTrash(accountId, id)        ← новое: перемещение, синкается как перемещение
deleteNodeRecursive(accountId, id) ← без изменений: настоящее удаление
```

- человек выбрал «В корзину» → `moveToTrash`;
- человек выбрал «Удалить навсегда» → `deleteNodeRecursive`;
- агент через MCP → `moveToTrash`, всегда;
- сгорание, срок жизни, подметальщик → `deleteNodeRecursive`, **как и было**.

Тест, который это удержит: сломать разделение так, чтобы сгорание уводило в корзину, — должно
покраснеть. Кросс-машинный тест сгорания, который `PLAN_ephemeral_secrets_tail` до сих пор должен,
становится от этого только нужнее.

#### Запись в корзине — инертна

Иначе «удалено» ничего не значит. В корзине запись: не отдаётся агенту ни на одном уровне, не
работает по CLI-алиасу, не участвует в отчёте о гигиене, не предлагается как цель зависимости и не
выдаётся действиями брокера. Видна человеку, и только.

Зависимости, указывающие на запись в корзине, ведут себя как висячие — цвет гаснет, связь
сохраняется, возврат из корзины её восстанавливает. Это уже работающая конвенция.

#### Одна папка, которую нужно спрятать в восьми местах

Корзина — обычный узел-папка, поэтому синк, дерево и перемещение работают даром. Плата: её надо
исключить из folder-пикеров, дропдауна зависимостей, наследования настроек MCP, отчёта о гигиене,
засева папок по умолчанию, правила «тип папки диктует тип записи» (в корзине лежит вперемешку) и
выдачи агенту.

Это ровно тот класс дефекта, о котором говорит `common/security.md` — «мера, применённая к ЧАСТИ
своих мест». Значит: **один предикат `isTrashFolder(node)`** и сканер, который валит сборку, если
появился новый перебор папок, его не вызывающий.

#### Срок хранения

Корзина, которая не очищается, — это папка живых секретов, которые человек считает удалёнными. Для
менеджера паролей это неприятный сюрприз, а не удобство.

**Правый клик по корзине → «Очищать через…»**, выбор из: **1, 3, 7, 30, 90, 365 дней**. Плюс
команда **«Очистить корзину сейчас»**.

Срок хранится **на самой папке-корзине**, а не в настройках VS Code, и это осознанно: у каждого
аккаунта своя корзина, а значит свой срок, и он должен ехать вместе с хранилищем на другую машину.
Настройка редактора этого не умеет — она про машину, а не про аккаунт.

```ts
// TreeNode, не EntityMetadata: корзина — папка, а не запись.
/** Через сколько дней запись в корзине удаляется по-настоящему. Отсутствие = не очищать. */
trashRetentionDays?: number;
```

Значит поле нужно и в `isTreeNode` — тот же валидатор на границе синка и импорта, что и для
`EntityMetadata`, и та же цена за пропуск: молча срежется.

Автоочистка вызывает **`deleteNodeRecursive`** — то есть по истечении срока запись удаляется
по-настоящему, со всеми ключами и историей. Корзина отодвигает необратимость, а не отменяет её.

Подметальщик уже есть — `ephemeralSweeper.ts` ходит по расписанию и удаляет то, чему вышел срок.
Корзина добавляет ему второй повод, а не второй подметальщик.

## Что не должно быть доступно никогда, ни на каком уровне

| нельзя | почему |
|---|---|
| прочитать пароль, приватный ключ, строку подключения с паролем, seed TOTP | это ровно та выдача, ради недопущения которой продукт существует |
| выгрузить хранилище, снять или прочитать бэкап | одна операция вместо тысячи |
| удалить запись, папку, аккаунт | удаление расходится синком на все машины и уносит историю версий — откатывать будет нечем |
| прочитать историю версий | это старые пароли, они пароли и есть |
| сменить место синхронизации, снять пин с host key | тихо ломает границу доверия |
| удалить папку или аккаунт | уровень 5 — про одну запись; папка уносит всё, что в ней |

## Управление сверху

**Настройка на папке, и она наследуется.** Не «применить ко всем сейчас», а именно наследование:
запись, созданная в папке позже, получает её разрешения. Иначе через неделю половина папки
настроена, а половина нет, и по виду не отличить.

Значит нужна **форма редактирования папки**, которой сегодня нет вовсе — папка только создаётся и
переименовывается. Панель по образцу формы сущности, но пока **с единственной секцией MCP**:

- те же пять переключателей, та же лестница, те же цвета;
- запись без собственной настройки берёт папочную; запись со своей — свою.

> **Сделано, 0.67.0.** `folderFormPage.ts` (чистый рендер) + `folderFormPanel.ts` (webview), по
> образцу `entityFormPage`/`entityFormPanel`. Отклонения от написанного выше:
>
> - Переключателей **шесть**, а не пять — как и в форме записи: удаление разделено на «своё» и
>   «любое». Полосок по-прежнему пять.
> - Форма держит **и имя папки тоже**, а не одну секцию MCP: ввод имени был единственным, что у
>   папки было, и оставить его в отдельном окошке рядом с новой формой значило бы два места для
>   редактирования одной папки.
> - **Тип папки в форму не вошёл сознательно.** Он определяет, какие сущности папка вправе
>   держать; смена задним числом оставит внутри содержимое, которое папка уже не принимает. Это
>   отдельная задача с вопросом о миграции, а не поле, которое дописывают заодно.
> - Внутри **корзины** переключателей нет — вместо них фраза. Там они не решают ничего:
>   `resolveMcpAccess` отвечает «недоступно» для всего, что лежит в корзине, и тест
>   (`folderFormPage.test.ts`) сверяет фразу с тем, что делает резолвер.
> - Форма называет **радиус поражения** до того, как тронут переключатель: сколько записей в
>   папке он накроет. Настройка на папке — единственное место здесь, где галочка выдаёт права
>   записям, на которые никто не смотрит, включая ещё не созданные.
> - Наследование **на один уровень**: запись берёт настройку своей непосредственной папки,
>   вложенная папка родительскую не наследует. Так написан `resolveMcpAccess`, и счётчик в форме
>   считает то же самое — прямых записей папки.

Из этого следует, что поле `mcp` на записи должно уметь состояние **«не задано»**, отличное от
«всё выключено»: первое означает «спроси папку», второе — «я решил, что ничего». Различие
делается наличием самого поля, а не значениями внутри него.

**Общий рубильник.** Одна команда, гасящая весь MCP-доступ мгновенно, не трогая настройки записей —
чтобы после «выключить» их можно было вернуть одним движением, а не восстанавливать полсотни
галочек. Для менеджера паролей это обязательная вещь.

## Как это выглядит в форме

Здесь возможно всё, потому что форма — это webview, обычные HTML и CSS.

**Переключатели красятся своим цветом, и только они.** Свойство `accent-color` красит сам контрол,
не трогая подпись и описание:

```css
#mcpView   { accent-color: var(--vscode-credSshManager-depColor5); }  /* зелёный */
#mcpUse    { accent-color: var(--vscode-credSshManager-depColor4); }  /* голубой */
#mcpEdit   { accent-color: var(--vscode-credSshManager-depColor2); }  /* янтарный */
#mcpCreate { accent-color: var(--vscode-credSshManager-depColor7); }  /* фиолетовый */
#mcpDelete { accent-color: var(--vscode-credSshManager-depColor3); }  /* красный */
```

**Полоса из пяти сегментов** — тоже обычная разметка: пять элементов с промежутками, каждый своего
цвета, погашенные до едва заметных, когда соответствующий переключатель выключен. Рисуется под
названием записи в шапке формы, так что состояние доступа видно, не прокручивая до секции.

## Секция MCP во вьюере

Вьюер — карточка по двойному клику — тоже показывает секцию MCP, только для чтения: те же полоски
и те же цвета, что в форме, плюс список включённого словами.

**И одну вещь, которой в форме нет: откуда разрешение взялось.** В форме видно контролы, а во
вьюере нужен ответ, а не устройство:

```
MCP    ▍▍▍▍▍   виден · можно пользоваться
       унаследовано от папки «vpn»
```

против

```
MCP    ▍▍▍▍▍   виден · можно пользоваться · можно обновлять секрет
       задано на этой записи
```

Это различие — то самое «не задано» против «явно выключено», ради которого поле `mcp` умеет
отсутствовать. В форме его видно по тому, тронуты ли галочки; во вьюере, где галочек нет, его надо
сказать словами, иначе карточка врёт одинаково в обоих случаях.

**Куда это ложится в коде.** Вьюеров два — живой и вьюер версии из истории, — и их общая
арифметика вынесена в `viewerOptions.ts` (audit A1: раньше лестница «поле → секрет» лежала в двух
копиях). Сводка MCP считается там же, одним чистым куском, и обоим достаётся из одного места.

**У вьюера версии есть нюанс, который стоит решить сразу.** Снимок в историю берёт весь
`EntityMetadata`, то есть старые флаги MCP в нём есть. Показывать их как есть — честно («вот чем
запись была»), но читается как текущее разрешение и может напугать. Предлагается: показывать, но с
пометкой, что это состояние на момент версии, а не сейчас — так же, как вьюер версии уже помечает
всё остальное.

## Как это видно в дереве — и почему не так, как в форме

**Пяти цветов на строке дерева получить нельзя.** Это не сложность, а отсутствие API:

| канал строки | что даёт | занят |
|---|---|---|
| `ThemeIcon` + `ThemeColor` | **один** цвет значка | историей версий |
| `FileDecoration.color` | **один** цвет текста названия | зависимостями |
| `FileDecoration.badge` | до **двух** символов, **один** цвет на оба | зависимостями |
| `TreeItemLabel.highlights` | диапазоны в названии, стиль задаёт тема — **не свой цвет** | свободен |

Пер-сегментной и пер-символьной раскраски нет ни в одном из них.

**Но сгенерированная иконка — возможна, и это было сказано слишком коротко в первой редакции
плана.** `iconPath` принимает файл, и в этом проекте так уже делается: `account-green.svg` и
`account-grey.svg` подключаются через `Uri.joinPath(extensionUri, 'media', …)`. Значит пять точек
своими цветами нарисовать можно. Вопрос не «можно ли», а **чем платим**: иконный слот один, и он
несёт значок типа записи.

**Решение: составной значок «тип + пять полосок», сгенерированный на все комбинации.**

Полоски, не точки: пять коротких вертикальных штрихов с промежутками, каждый своего цвета,
погашенный до едва заметного, когда соответствующий переключатель выключен.

**Значок будет слева, а не справа — справа его быть не может.** `iconPath` рисуется слева всегда.
Справа у строки только серая приписка и бейдж декорации; бейдж — текст до двух символов **одного**
цвета, и именно он перекрывается кнопками действий при наведении. То есть место, которое имелось в
виду, — это место бейджа, и пять разноцветных полосок туда не помещаются по устройству API.

Обходной путь существует и отвергается: контрибутить 32 псевдо-действия `group: inline`, по одному
на комбинацию маски, каждое со своим значком и `when` по `contextValue`. Это 32 команды и 32 пункта
меню в манифесте ради украшения, спорящих за место со Start/Stop.

**Генерация — скриптом на сборке, а не лениво в рантайме.** `scripts/generate-icon.mjs` уже
существует и делает ровно это для `media/icon.png`; рядом встаёт второй скрипт. Комбинаций
7 типов × 32 маски = 224 файла, каждый около трёхсот байт — порядка 70 КБ в пакете, и они
коммитятся, как коммитится `media/icon.png`.

Что нужно нарисовать: **семь глифов типов**. Сейчас для них берутся codicon'ы VS Code, исходников
у нас нет. Три уже есть в `media/` (`db-green.svg`, `account-*.svg`, `play-green.svg`) — остальные
четыре рисуются в том же стиле. Это единственная работа в этом пункте, которую нельзя
автоматизировать, и результат надо посмотреть глазами рядом с обычными строками дерева: свой глиф,
выбивающийся из набора редактора, хуже отсутствия полосок.

> **Сделано, 0.68.0.** `src/mcpIcons.ts` (чистый: имена, глифы, геометрия) +
> `scripts/generate-mcp-icons.mjs` + `media/mcp/*.svg`. Отклонения:
>
> - **140 файлов, а не 224.** Оценка «7 типов × 32 маски» была сделана до того, как доступ стал
>   лестницей. Лестница делает маску монотонной по построению, поэтому у пяти бит **шесть**
>   значений, а не тридцать два: 7 типов × 5 уровней × 2 темы × 2 состояния истории = 140.
> - **Уровень 0 значка не получает.** Запись, до которой агент не дотянется, — а это каждая
>   запись, пока не сказано иначе, — сохраняет codicon редактора и тинт истории как было. Свои
>   глифы появляются только там, где им есть что сказать; иначе форма, слегка выбивающаяся из
>   набора редактора, растеклась бы по всему дереву.
> - **Тинт истории пришлось вписать внутрь файла.** К файловому значку `ThemeColor` не
>   применяется, так что глиф просто рисуется этим цветом — иначе шаг «полоски» тихо отобрал бы
>   уже работающий сигнал «у записи есть предыдущие версии».
> - **Глифов нарисовано семь, а не четыре.** `db-green.svg` подошёл (переиспользован как есть),
>   `account-*.svg` и `play-green.svg` — нет: первый не тип записи, второй значок действия
>   «запустить», а не «скрипт».
> - **Цвета полосок берутся из `package.json`**, из `contributes.colors`, через каталог
>   переключателей. Ни одного hex в генераторе: палитра у формы, карточки и дерева одна, и тест
>   читает файлы обратно и сверяет.
> - **Обе темы отрисованы и просмотрены глазами** до выпуска.
> - Побочно исправлено: `getNode` был линейным поиском по всему профилю. Пока он отвечал на
>   один вопрос за раз — нормально; как только строка дерева стала спрашивать по разу на
>   перерисовку, это миллион сравнений на нажатие клавиши в фильтре. Теперь Map.

## Модель данных

`EntityMetadata` получает одно поле:

```ts
/**
 * Что разрешено агенту через MCP. Лестница: delete ⊂ create ⊂ edit ⊂ use ⊂ view.
 * Отсутствие поля означает «ничего», а не «по умолчанию» — новая запись невидима агенту.
 */
mcp?: {
  view?: boolean;
  use?: boolean;
  edit?: boolean;
  create?: boolean;
  /** 'any' — любую запись; 'own' — только созданные агентом. Отсутствие — удалять нельзя. */
  delete?: 'any' | 'own';
};

/** Запись завёл агент (уровень 4). Только такие он и может удалить — см. уровень 5. */
mcpCreatedByAgent?: boolean;
```

Три обязательных места, каждое из которых уже однажды роняло поле:

1. **`isEntityMetadata`** (`types.ts:553`) — иначе синк и импорт молча срежут флаги.
2. **`toValues`** (`entityFormPanel.ts`) — собирает `details` явным списком, незаписанное там
   теряется при каждом сохранении формы.
3. **`shareableDetails`** (`shareFormat.ts`) — **флаги обязаны вырезаться при шаринге.** Иначе
   отправленная запись приезжает в чужое хранилище уже разрешённой их агенту. Это та же ошибка,
   что закрыта для `dependsOn`, но цена здесь выше.

## Где живёт MCP-сервер

**Не в расширении.** У расширения **ноль рантайм-зависимостей** — осознанное ограничение, из-за
которого уже отказались от формата KDBX (Argon2 нет в Node, пакет тянуть нельзя). MCP SDK стал бы
первой зависимостью за всю историю. И время жизни не то: MCP-клиент запускает сервер как свой
дочерний процесс, а расширение живёт внутри VS Code.

**Отдельным бинарём `creds-mcp`** — решение владельца 2026-08-26. Первая редакция плана предлагала
глагол `creds mcp` и отвергала отдельный бинарь как «третье место, где чинить одну и ту же ошибку».
Возражение снимается не отказом от решения, а устройством: общий код выносится в библиотеку.

```
src_cli/src/         CredsCli.csproj      →  creds
src_mcp/src/         CredsMcp.csproj      →  creds-mcp
src_broker_client/   BrokerClient.csproj  ←  оба ссылаются сюда
```

В библиотеку переезжают `BrokerClient.cs`, `BrokerContract.cs`, `GrantToken.cs`, `Endpoints.cs`
(поиск живого окна), `WslInterop.cs`. Исправление в клиенте брокера по-прежнему делается в одном
месте — а бинарей два, у каждого своя папка и свой релиз, как и просили.

**Сборка — как у CLI, тем же форматом:** Native AOT, четыре RID (`win-x64`, `win-arm64`,
`linux-x64`, `linux-arm64`), отдельная job в `release.yml` по тегу `mcp-v*`, со своими тестами
перед публикацией и smoke-проверкой `--help` там, где раннер может выполнить бинарь. Версионируется
независимо от расширения, CLI и сервера — четвёртая линия тегов.

**Кнопка установки в верхнем меню**, как у CLI: команда, которая кладёт бинарь куда надо, дописывает
конфиг MCP-клиента и говорит, что получилось. Расширение при этом не меняется по зависимостям —
их по-прежнему ноль.

```json
{ "mcpServers": { "creds": { "command": "creds", "args": ["mcp"] } } }
```

.NET-сторона берёт официальный `ModelContextProtocol` NuGet — ровно то, что делает `dew_flow_mcp`,
то есть в семье уже есть работающий образец (`src/Mcp.Server/`, `src/Mcp.Application/ToolCatalog.cs`).

> **Сделано, 2026-08-27.** `src_broker_client/` (библиотека), `src_mcp/` (бинарь), job `mcp-v*`,
> кнопки установки в ⋯ меню, маршрут `GET /v1/mcp/entries` в брокере. Отклонения и измерения:
>
> - **Пакет проверен, а не принят на веру.** Опасение было, что SDK не переживёт AOT. Измерено:
>   `PublishAot` + `JsonSerializerIsReflectionEnabledByDefault=false` — ноль trim-предупреждений,
>   13 МБ бинарь, и опубликованный бинарь честно отвечает на реальный `initialize` / `tools/list`.
>   Оба правила CLI сохранены.
> - **Два побочных факта, найденных тем же измерением.** Хостинговый дефолт SDK пишет логи в
>   **stdout** — а там протокол; одна строка ломает поток, и выглядит это как баг протокола, а не
>   логирования. Поэтому сервер собирается вручную (`McpServer.Create`), а не через generic host,
>   и итест проверяет, что в stdout нет ничего кроме JSON-RPC. Второй: закрытие stdin гасит сервер
>   на полпути и ответы не успевают уйти — выглядит в точности как сломанный handshake.
> - **Инструмент один — `creds_list`**, и это осознанно. Глаголы уровня 2 в брокере есть, но
>   сегодня они закрыты только модальным окном согласия, а не переключателями записи. Опубликовать
>   их раньше, чем они начнут спрашивать переключатели, значило бы дать агенту пользоваться
>   записью, которую переключатели запрещают, — ровно то, против чего вся эта конструкция.
> - **Маршрут read-only не носит токена**, и это решение записано в `isMcpEntriesRoute`: заменяет
>   токен сам факт переключателя. Ничего не появляется, пока человек не включил его для записи, —
>   значит раскрывается не «что лежит в хранилище», а «что владелец показал агенту».
> - **Заметки не отдаются** (только `hasNotes`) — отклонение от примера в разделе «Уровень 1»
>   выше: заметки с 0.20 живут в SecretStorage и вырезаются при шаринге, то есть продукт считает
>   их секретом везде; одна строка в `mcpEntries.ts` возвращает их, если владелец решит иначе.
> - **Конфиг MCP-клиента предлагается, а не дописывается.** План говорил «дописывает конфиг».
>   Файл принадлежит чужой программе, клиентов может быть несколько, а менеджер паролей, молча
>   правящий конфиг, который выдаёт агенту доступ к нему самому, — неправильный инстинкт в
>   неправильном месте. Блок кладётся в буфер, рядом называется файл.
> - **Кнопка установки CLI появилась заодно**: `credsInstall.ts` был написан и покрыт тестами
>   давно и не был подключён ни к чему.

   обязательный снимок в историю до записи, согласие на каждый вызов.
8. **`creds mcp`** — каталог инструментов как данные, stdio, маршрутизация в брокер.
9. **Команда «Настроить доступ MCP…»** в расширении: показывает готовый JSON и объясняет, что
   даёт и чего не даёт.
10. **Интеграционный тест** по образцу `scripts/creds-cli-itest.cjs`: реальный stdio-обмен.
11. Документация: `research/module_extension.md`, README, changelog.

## Тест-план

| что | чем проверяется |
|---|---|
| лестница не собирается «наоборот» | тест `mcpAccess.ts` |
| выключено по умолчанию | тест: новая запись невидима агенту |
| ни один ответ уровня 1 не отдаёт секрета | тест по образцу `treeSearch.test.ts` |
| пароль вырезан из строки подключения | `withoutPassword` уже покрыт; добавить прогон через MCP-путь |
| флаги вырезаются при шаринге | по образцу теста для `dependsOn` |
| действие без согласия не выполняется | уже есть в брокере; тот же прогон через MCP |
| перезапись всегда оставляет снимок в истории | сломать снимок → должно покраснеть |
| каталог не содержит инструмента без реализации | тест каталога |
| отказ читается как отказ, а не «неизвестно» | это уже ловили однажды в реестре грантов |

## Риски

1. **Флаги в шаре — самая дорогая ошибка в этом плане.** Пропустить их в `shareableDetails`
   значит раздавать предавторизованные записи. Тест обязателен, не «не забыть».
2. **Второй клиент делает срочным версионирование контракта** — пункт E3 дорожной карты.
3. **Согласие — один раз за сессию** (решение владельца): цель не подтверждать каждое чтение, а
   чтобы человек **знал, что MCP используется вообще**. Первый вызов за сессию показывает диалог,
   дальше молчим до перезапуска окна.
   Действия уровней 3–5 из этого исключены: перезапись секрета, создание и удаление спрашивают
   каждый раз — «один раз за сессию» относится к чтению, а не к записи.
   Риск остаётся тот же, что был: соблазн растянуть «один раз» на «навсегда». У брокера есть
   гранты со сроком жизни, и срок сессии — это срок окна, а не календарный.
4. **`creds` не в PATH** — самая частая причина «MCP не работает»; диагностика должна называть это
   прямо.
5. **Подсветка названия выглядит как совпадение поиска.** Решается глазами после сборки.

## Решения владельца

**Получены 2026-08-26:**

- Лестница, а не независимые галочки.
- Уровень 3 — **только перезапись секрета**; создание и удаление вне объёма.
- Всё выключено по умолчанию.
- Умолчание на папку и общий рубильник — оба в этой задаче.
- Отметка в дереве — текстом, а не иконкой (реализуется подсветкой: подчёркивания в API нет).

**Получены 2026-08-26, вторым заходом:**

- Переключателей пять: добавлены **создание** и **удаление** отдельными пунктами.
- Цвета: просмотр зелёный, удаление красное, остальные — из палитры, эскалацией.
- Переключатели в форме красятся своим цветом; подпись и описание — стандартные.

**Получены 2026-08-26, третьим заходом:**

- Настройка папки **наследуется** записями, созданными позже; для этого появляется форма
  редактирования папки — пока с единственной секцией MCP.
- Секреты генерирует **расширение**; агент получает ссылку, не значение, и вставляет ссылку.

**Получены 2026-08-26, четвёртым и пятым заходом:**

- **Корзина**: папка на аккаунт, агент удаляет только в неё, человека спрашивают «В корзину»
  (кнопка по умолчанию) или «Удалить навсегда».
- Срок автоочистки — правым кликом по корзине: 1, 3, 7, 30, 90, 365 дней.
- **Эфемерные записи корзину минуют** — подтверждено владельцем как отдельное решение.
- **Значок**: составной «тип + пять полосок», все комбинации генерируются скриптом.
- **Удаление — две галочки** («всё» / «только своё»), делящие одну полоску и один цвет.
- **Если расширение не умеет сгенерировать — генерирует агент**, и это видно в журнале
  отдельной категорией.
- **Согласие — один раз за сессию**, чтобы человек знал, что MCP используется вообще; на каждое
  чтение не спрашиваем.
- **Секция MCP есть и во вьюере**, для чтения — с указанием, задано разрешение на записи или
  унаследовано от папки.

- **Глифы рисуются без согласования** — владелец смотрит их уже в собранной версии.
- **Журнал живёт в существующем логе расширения**, отдельного места не заводится.

**Открытых вопросов нет.** План готов к сборке.
